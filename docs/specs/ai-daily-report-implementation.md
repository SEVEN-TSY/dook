# 一键写日报实现流程

使用现有Electron、TypeScript、React和SQLite。产品规则与验收口径见[一键写日报规格](./ai-daily-report.md)。

## 一次日报请求怎么走

```text
设置页保存DeepSeek API Key → 主进程加密并保存到本机

用户看到发送范围说明后点击「写日报」
  → 卡片显示「正在生成日报…」和「取消」
  → 等待两窗口中会影响日报素材的已有编辑保存
  → 通过IPC发起生成，传入本地日期和requestId
  → 主进程核对日期，从SQLite读取任务快照并计算统计
  → 检查材料范围和大小，用本次请求内的任务编号异步调用DeepSeek
  → 收到完整响应后，校验JSON、任务来源和分类
  → 程序拼装标题、统计和章节，逐项附上未完成多天任务的当前进度
  → 展示日报草稿，用户可以编辑、复制或重新生成
```

- **缺少Key**：提示前往设置，配置后由用户再次发起生成。测试连接使用固定消息，不发送任务内容。
- **保存失败、日期变化、没有材料或材料超限**：在调用DeepSeek前结束请求，在卡片内说明原因。
- **取消**：保存阶段取消生成意图，后续不发送请求。联网阶段由主进程中止请求。界面忽略晚到结果并保留已有草稿。
- **请求失败或结果校验失败**：保留已有草稿，提示原因，允许用户重试。重试时重新读取任务快照。
- **重新生成成功**：已有草稿经过手动修改时，先由用户确认是否替换。

## 开发顺序

| 顺序 | 实现内容 | 完成标志 |
| --- | --- | --- |
| 1 | 定义共享契约，包括生成和取消参数、草稿结果、错误码及凭证配置状态 | 主进程和界面使用同一套TypeScript类型与运行时校验 |
| 2 | 新增SQLite日报查询和主进程生成用例，固定日期、任务快照和统计，接入可替换的模型调用接口 | 用真实SQLite和可控模型响应跑通任务筛选、超限检查与结果校验 |
| 3 | 实现DeepSeek适配器与本地凭证存储 | Key可保存、替换、清除和测试。请求使用非流式响应，支持超时与取消 |
| 4 | 通过preload与白名单IPC接通设置、生成和取消 | 每个主窗口最多一个进行中的请求。取消按窗口和`requestId`定位 |
| 5 | 接入设置页和任务页日报卡片 | 用户在首次发送前能看到数据范围，生成时可以取消，成功后可以编辑和复制 |
| 6 | 跑通Electron完整链路 | 覆盖配置、生成、取消、失败重试和草稿保护，再用有效Key手动生成一次真实日报 |

DeepSeek的网络请求在Electron主进程异步等待，使用`AbortController`取消。界面通过IPC等待最终结果，生成期间仍可操作。SQLite快照读取结束后就释放事务，再发起网络请求。
