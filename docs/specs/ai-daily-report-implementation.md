# 一键写日报实现流程

使用现有Electron、TypeScript、React和SQLite。产品规则与验收口径见[一键写日报规格](./ai-daily-report.md)。本文对应当前实现（#42及后续修订）。

## 一次日报请求怎么走

```text
在设置页创建AI配置并选为默认模型 → 主进程验证并加密保存API Key

用户点击任务页日报入口
  → 卡片展开，显示服务商、发送范围与材料数
  → 关闭“显示持续推进”且有隐藏的多天任务时先确认
  → 主进程请求主界面和便签保存相关编辑，只等任务、子事项和习惯
  → 再次核对日期、范围、默认配置和隐藏多天任务
  → 读取当天任务快照，编号并组装材料，检查100项/2000/16000/256KiB限额
  → 读取日报场景的有效提示词
  → 系统指令 + 写作要求 + 任务材料交给AiConnection
  → 流式JSON请求，按收到的片段显示等待、推理或生成状态，可取消
  → 收到结束标记后校验响应体、完成原因、JSON结构、来源、子事项和今日进度
  → 按两节拼装标题和条目正文，写入daily_reports
  → 卡片展示正文，自动保存编辑，可复制或重新生成
```

- 缺少默认配置时卡片给出设置入口；没有材料、超限、保存失败和已有请求都在联网前结束；跨日在发起前和响应返回后各核对一次。
- 单次尝试60秒超时，网络失败与限流沿用自动重试。仅正文片段参与拼装，推理片段只用于更新状态。
- 取消、无效输出、失败和晚到结果都保留已有正文；生成期间的手动编辑优先，本次结果不再采用。
- 重新生成成功后覆盖同一天记录；重新打开应用后按日期读回，卡片默认收起。

## 分层与文件

| 位置                                         | 职责                                                     |
| -------------------------------------------- | -------------------------------------------------------- |
| `main/core/daily-reports.ts`                 | 日期与范围、任务快照、材料数、生成与采用条件、按日期保存 |
| `main/core/daily-report-material.ts`         | 素材组装、输出Schema、来源与今日进度校验、正文渲染       |
| `main/desktop/daily-report-session.ts`       | 准备与复核、保存屏障、单活跃请求、取消与结果采用         |
| `main/ai/connection.ts`                      | 默认配置与凭证、HTTP请求、超时重试、取消、调用日志       |
| `main/ai/scene-prompts.ts`                   | 场景提示词及默认／自定义模式                             |
| `main/storage/repositories/daily-reports.ts` | `daily_reports`读写与当天进度增量                        |
| `main/storage/repositories/tasks.ts`         | 日报候选查询、进度基线写入                               |
| `shared/daily-report.ts`                     | 跨进程契约与正文12000码点限额                            |
| `main/desktop/ipc.ts`                        | 主窗口来源校验、参数校验和频道                           |

## 校验点

- 联网前：日期、空材料、任务数、单条与合计长度、请求体大小、默认配置、并发请求和保存结果。
- 联网前复核：日期、范围、配置指纹、隐藏多天任务确认。
- 响应后：1 MiB响应体、64 KiB正文、完成原因、JSON结构、来源资格与章内去重、子事项、多天任务单独成条、今日进度数值和12000码点正文。
- 采用条件：未取消、日期未变、生成开始后未编辑、未被新请求取代；响应返回后发现跨日则报错且不写库。
- 失败处理：不写库、不覆盖正文、不自动再次请求模型修复；只保留调用日志。

## 日志与错误

- 每次调用写一条 `ai_call_logs`（事件为`daily_report`），含配置、模型、耗时、结果、HTTP状态和Token用量，不含提示词、任务原文与响应正文。
- 鉴权、余额、证书、限流、网络、超时、服务不可用和无效响应映射为可执行的用户提示；取消是独立结果。
- 业务核心不读HTTP、不写业务SQL；桌面适配层负责加密与窗口保存；渲染层只负责触发、编辑和复制。

## 验证

- `npm test`覆盖材料范围、当天净增量、隐藏多天任务、无效输出、取消与重启后读取。
- `npm run typecheck`保证跨进程契约类型一致。
- 使用有效凭证手动生成一次真实日报，核对调用日志和正文，不保存凭证。
