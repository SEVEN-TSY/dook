# 灵感主页面：日期与主题归集管理

状态：产品决定及测试边界已获用户确认，已发布为[GitHub Issue #14](https://github.com/SEVEN-TSY/myTodo/issues/14)，标签为ready-for-agent。

## Problem Statement

用户需要快速留住突然冒出的主意，例如产品构想或想到要补充的需求，记录时未必清楚具体含义或落地方式。现有主页面缺少日期和主题归集，随着记录增加，回看和聚合相关灵感越来越困难。

任务侧重今天的工作规划，灵感侧重先记录以免遗忘。为灵感增加转任务流程或强制区分“想法／速记”会偏离当前使用目的。用户希望既能按日期回顾，也能将相关独立灵感长期积累到主题中，未来再整理成项目需求。

## Solution

主页面默认按日期归集，今天及前6天独立成组，今天默认展开，其他日期默认折叠。更早的记录统一进入“历史灵感”。提供独立的主题视角，按主题归集并包含“未归类”，所有主题组默认折叠。长列表通过下滑逐页加载。

新增灵感只输入内容即可。用户可将灵感归入已有主题，或归入新主题并创建主题，也可取消归集；允许低频地归入多个主题。同一条灵感在不同主题中保持同一份内容。

列表点击正文原地编辑，行尾“补充”按钮打开右侧详情。保留详情中的完整原始想法只读展示、历史补充和追加输入，去掉详情内编辑原始想法的功能。

## User Stories

1. 作为记录灵感的用户，我希望只输入一句主意就能保存，以便在含义尚不明确时先记下来。
2. 作为记录灵感的用户，我希望无需选择想法或速记类型，以便保持记录过程轻量。
3. 作为回顾灵感的用户，我希望默认按日期归集，以便知道哪些主意是什么时候记录的。
4. 作为回顾灵感的用户，我希望今天及前6天分别按日期成组，以便快速回顾近期记录。
5. 作为回顾灵感的用户，我希望日期从新到旧排列，以便先看到最近的记录。
6. 作为回顾灵感的用户，我希望今天默认展开，以便打开页面就能看到当天灵感。
7. 作为回顾灵感的用户，我希望其他日期默认折叠，以便保持列表简洁。
8. 作为回顾灵感的用户，我希望各日期可以独立展开或收起，以便同时查看需要的日期。
9. 作为回顾灵感的用户，我希望7天之外的记录归入默认折叠的历史灵感，以便近期日期不会被过多旧分组淹没。
10. 作为已有记录的用户，我希望无法还原日期的旧灵感归入历史灵感，以便保留内容且不产生虚假的记录日期。
11. 作为持续补充灵感的用户，我希望编辑、追加补充或调整主题不改变记录日期，以便保持最初记录的时间语境。
12. 作为整理灵感的用户，我希望能切换到独立的主题视角，以便直接浏览相关灵感的集合。
13. 作为整理灵感的用户，我希望主题视角中的所有组默认折叠，以便先看到主题结构。
14. 作为整理灵感的用户，我希望有未归类组，以便发现尚未整理的记录。
15. 作为记录灵感的用户，我希望新增时可以不归入主题，以便先捕捉主意再整理。
16. 作为整理灵感的用户，我希望将灵感归入已有主题，以便相关独立记录持续积累在一起。
17. 作为整理灵感的用户，我希望归集到新主题时就能创建该主题，以便顺着整理过程建立集合。
18. 作为整理灵感的用户，我希望取消灵感对某个主题的归集，以便修正不合适的关联。
19. 作为整理灵感的用户，我希望在日期视角和主题视角都能归集或取消归集，以便无需专门切换视角完成整理。
20. 作为偶尔需要跨主题整理的用户，我希望一条灵感能归入多个主题，以便保留它与不同构想的关联。
21. 作为跨主题查看灵感的用户，我希望修改同一灵感后各处同步更新，以便不会出现多份不一致的内容。
22. 作为整理主题的用户，我希望仅在主题视角修改主题名称，以便集中管理主题。
23. 作为浏览灵感的用户，我希望组内按记录时间从新到旧排列，以便先看到最新主意。
24. 作为浏览灵感的用户，我希望列表正文最多显示三行，以便兼顾内容预览和列表密度。
25. 作为修改灵感的用户，我希望点击正文原地编辑并看到完整内容，以便无需到详情修改原始想法。
26. 作为补充灵感的用户，我希望通过补充按钮打开右侧详情，以便查看完整原始想法及历史补充。
27. 作为补充灵感的用户，我希望在详情中继续追加内容，以便围绕同一条灵感持续完善。
28. 作为浏览长列表的用户，我希望下滑时逐页加载，以便无需一次等待全部记录展示。
29. 作为长期积累构想的用户，我希望主题可以长期保留相关灵感且无需立即成为项目，以便等需求具体后再整理。

## Implementation Decisions

- 业务范围是主界面灵感管理；沿用灵感、原始想法及所属补充的现有关系。主题作为相关独立灵感的具名集合，与灵感形成多对多关系，归集不复制灵感。
- 日期视角与主题视角是两种归集浏览结构，主题视角不做成日期列表的筛选条件。
- 新记录需要持久化可用于本地自然日归组的原始记录时间，并提供同一时间下的稳定排序。原始记录时间不因后续修改而改变。
- 当前灵感没有记录时间，历史迁移不得推测其日期；保留原始内容及补充关系，将其归入历史灵感。为旧记录保留确定的排序依据。
- 扩展共享数据契约、存储、应用服务和桌面桥接，以支持日期归集、主题及关联操作、分页查询；继续沿用统一业务入口和SQLite持久化边界，不由界面直接访问数据库。
- 分页需要贯穿数据读取和界面加载，支持下滑继续读取；在固定数据集下遍历各页应无遗漏、无重复，切换视角后不得混入上一视角的异步结果。
- 继续沿用现有草稿保存、失败保留及跨窗口变更通知机制；主题归集和改名应持久化，同一灵感的正文变更在各处读取一致。
- 列表正文最多三行，编辑时完整展开；详情入口为行尾补充按钮，保留右侧详情面板，原始想法只读，补充历史和追加能力保留。
- 上述技术方案用于实现已确认的行为；分页大小、查询参数形式和数据库字段命名留给实现阶段决定，不视为用户已确认的产品要求。

## Testing Decisions

以下测试边界已获用户确认。

- 以现有真实Electron主界面操作链路作为主要验收边界，贯穿界面、桥接、应用服务及真实SQLite，不额外搭建一套测试接口。已有灵感场景覆盖跨窗口同步、补充、保存及重启恢复，可在该基础上扩展。
- 只检验可观察行为：两种视角下的分组、默认折叠、编辑入口、详情内容、主题创建与取消归集、主题改名限制，以及多主题中的同一记录同步更新。
- 用超过一页的数据验证下滑加载、页间无重复和遗漏、加载结束、切换视角后数据正确；不用内部调用次数或组件私有状态作为验收标准。
- 仅对界面测试难以稳定制造的日期边界和旧库迁移，补充现有AppService公开接口配合真实SQLite的集成测试，复用可注入时钟；覆盖今天、前6天、前7天、跨日归组和旧记录保留。
- 重启后读取主题、关联、正文和补充，验证保存结果；不为每一层重复编写镜像测试，不测试具体SQL或内部组件拆分。

## Out of Scope

- 灵感转为任务、完成状态和今天工作规划功能。
- 将灵感进一步拆分为想法与速记。
- 创建项目、生成需求文档或自动将主题落成项目的流程。
- AI聚类、自动推荐主题、自动整合灵感或落地建议。
- 桌面便签的布局改版和本轮未讨论的MCP业务工具。
- 主题删除、合并、手动排序等未确认的管理功能。
- 本轮不修改正式需求文档、根术语表，也不实现功能代码。

## Further Notes

- 产品决定来自2026-10-28的讨论及独立ADR；Q16补充确定为“通过下滑逐页加载”。
- 主题之间的排序、空主题处理、视角切换后的折叠状态是否记忆、历史组是否再细分日期均未确认，不能将建议当作既定需求。
- 新主题及多主题操作的具体视觉样式尚未指定；实现应保持快速输入和低频多主题操作的定位，并遵循项目主界面设计语言。
- 本规格记录未来实现范围，不代表功能已经完成。发布Issue时附ready-for-agent标签。
