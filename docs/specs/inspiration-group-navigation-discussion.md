# 灵感分组导航交互讨论

2026-11-01。状态：用户已统一确认交互清单及测试边界，已整理为《灵感分组导航改版：页内新增、主题管理与归档》，发布为[GitHub Issue #18](https://github.com/SEVEN-TSY/myTodo/issues/18)，标签为ready-for-agent；尚未实施。

## 已确认

- 用户选择原型C“分组导航”作为后续设计方向，并要求先交流对齐交互细节。
- 此选择尚不代表原型中的所有默认行为均已确认。
- 日期和主题视角在本次打开主界面期间分别记住选中的分组、灵感及滚动位置，切换时恢复；重新启动默认进入“今天”。
- 新增灵感入口统一位于分组标题同一水平线最右侧，使用“+”图标。日期视角仅“今天”显示；主题视角每个主题均可显示新增入口。
- 切换分组时关闭上一组灵感详情，先显示新分组的列表，通过该组条目的补充操作打开详情。
- 新增输入在页面内临时展开，弃用现有新增灵感输入方式。
- 新增输入区提供可见的“×”取消按钮，不使用Esc取消；点击“×”关闭输入区并直接丢弃未提交内容，不保留草稿，再次打开为空白。
- 保留分组导航布局方向，重新设计视觉样式，不沿用现有代码的控件样式；字体层级、留白、输入区、图标和Popover均需重新处理。
- 灵感操作以图标标识，默认显示“归主题”及其图标，hover时展示完整操作。具体文字保留范围待澄清。
- 增加归档灵感操作，采用逻辑删除，保留内容；日期分组导航末尾增加“已归档灵感”。
- 完成操作后在页面上部中间显示提示。
- 点击“归主题”按钮，在按钮处展开Popover，内部为支持搜索、创建选项的多选组合框。
- 主题视角的左侧分组支持删除和修改主题；分组导航区域增加“+”用于添加主题。
- 新增入口位置明确为：左侧分组导航区域的“+”用于新增主题，右侧灵感列表的分组标题行最右侧“+”用于新增灵感。
- 在某主题下新增灵感自动归入该主题。
- 已归档灵感通过日期视角末尾的“已归档灵感”分组查看；仅提供恢复和永久删除两个操作，默认展示恢复。永久删除必须二次确认。
- 删除主题仅解除该主题与灵感的归集关系，不删除灵感，也不影响其他主题关联；失去全部主题的灵感进入“未归主题”。删除主题前二次确认，提示关联的灵感数量。
- 归主题的多选组合框勾选或取消勾选即保存。
- 主题视角中每条灵感的日期需包含完整年月日。
- 新增保存后留在当前分组，清空输入框并保持展开；“未归主题”也提供新增灵感入口。
- 归档保留原日期、正文、补充与主题关联，恢复后按原日期和原主题归位。
- 在归主题Popover内创建主题后自动勾选，将当前灵感归入新主题。
- 成功提示约3秒后消失；失败提示可关闭，保存失败时输入保留在当前输入框，允许重试。主动点击“×”仍直接丢弃未提交内容，不保留草稿。
- 用户澄清“2-3”指此前Q2和Q3的问题编号，不代表秒数，不增加定时收回要求。操作区展开结束后回到默认显示。

## 与既有决定的关系

- ADR0001采用组内独立展开、主题组默认折叠。分组导航原型采用选中单个分组后显示其内容；需要在本轮明确替代规则。
- ADR0001中原地编辑、右侧只读原始想法及追加补充等决定继续作为讨论基线。

## 本轮未单独规定的细节

- 新增提交的具体按钮、键盘方式，以及切换分组时未提交内容的处理。
- 首次进入主题视角的默认选中项、主题排序和空主题的显示规则。
- hover展开后的文字保留范围、触屏与键盘操作细节。

上述细节不表述为用户已逐项认可；本次汇总仅列已明确讨论和确认的规则。统一确认后再整理实施规格。
