# 桌面便签：任务归档、习惯双击与分栏设置

状态：用户已确认规格及测试边界，已发布[GitHub Issue #24](https://github.com/SEVEN-TSY/myTodo/issues/24)，标签为ready-for-agent。

## Problem Statement

桌面便签中的普通任务删除后无法找回，用户需要一个可恢复的归档区，先移走任务，再按需永久删除。习惯任务单击描述就打开主界面，容易误触。便签目前固定显示“这就去做”和“持续推进”，用户希望选择隐藏持续推进，并在设置页清楚区分不同类型的配置。

## Solution

便签任务区默认提供“这就去做”“持续推进”“已归档”三个分栏。已归档默认折叠，标题只展示归档任务总数；展开后提供只读任务列表，每行默认展示恢复，hover时显示删除，支持再次删除以永久移除任务。普通任务原删除操作直接归档，不弹确认；永久删除沿用原生确认。

习惯生成的任务双击描述打开主界面习惯页，单击不打开。设置新增“显示持续推进”开关，默认开启；关闭后便签任务区只保留“这就去做”和“已归档”。设置按“系统偏好”和“便签偏好”分组，使用标题、留白和细分隔线划清边界。

## User Stories

1. 作为桌面便签用户，我希望默认看到三个任务分栏，以便区分当日工作、长期推进和已移走的任务。
2. 作为桌面便签用户，我希望已归档默认折叠，以便保留紧凑的日常工作区域。
3. 作为桌面便签用户，我希望已归档标题只显示归档总数，以便快速了解可恢复任务的数量。
4. 作为桌面便签用户，我希望没有归档任务时仍有数量为0的归档入口，以便清楚知道该功能的位置。
5. 作为桌面便签用户，我希望点击已归档标题展开或收起列表，以便按需查看归档内容。
6. 作为桌面便签用户，我希望删除普通今天任务时直接归档，以便减少日常操作并允许找回。
7. 作为桌面便签用户，我希望删除普通多天任务时同样归档，以便保留已经积累的进度和子事项。
8. 作为桌面便签用户，我希望归档后任务退出日常列表和任务进度统计，以便统计反映仍需关注的任务。
9. 作为桌面便签用户，我希望归档内容跨日和重启后仍保留，以便之后恢复或清理。
10. 作为桌面便签用户，我希望归档任务只读，以便归档区保持简单明确。
11. 作为桌面便签用户，我希望归档任务行默认提供恢复，以便优先找回误归档的任务。
12. 作为桌面便签用户，我希望hover时能看到删除，以便清理不再需要的归档任务。
13. 作为键盘用户，我希望聚焦操作区域也能访问恢复和删除，以便完成同样的操作。
14. 作为桌面便签用户，我希望恢复后任务离开归档区并回到对应任务分组，以便继续处理。
15. 作为桌面便签用户，我希望恢复保留描述、任务形态、完成状态、进度和子事项，以便继续原来的工作。
16. 作为桌面便签用户，我希望再次删除前确认永久删除，以便避免误清理仍有用的任务。
17. 作为桌面便签用户，我希望取消永久删除后任务和归档数量保持原样，以便撤回操作。
18. 作为双窗口用户，我希望归档、恢复和删除同步刷新主界面和便签，以便两处看到一致的数据。
19. 作为习惯用户，我希望单击习惯任务描述时留在便签，以便避免误开主界面。
20. 作为习惯用户，我希望双击描述打开主界面习惯页，以便有意管理习惯。
21. 作为习惯用户，我希望完成勾选和暂停一次继续正常工作，以便保持已有的每日流程。
22. 作为桌面便签用户，我希望在设置中关闭持续推进分栏，以便只关注这就去做和已归档。
23. 作为桌面便签用户，我希望隐藏持续推进时保留其中的数据，以便重新开启后继续推进。
24. 作为桌面便签用户，我希望修改分栏设置立即生效并在重启后保留，以便持续使用偏好的布局。
25. 作为已有用户，我希望旧配置自动采用三个分栏，以便升级后无需额外设置。
26. 作为设置页用户，我希望配置按系统偏好和便签偏好分组并清楚分隔，以便快速找到相关选项。
27. 作为桌面便签用户，我希望操作失败时保留原有数据并看到错误，以便重试。

## Implementation Decisions

- 桌面便签任务分栏固定顺序为这就去做、持续推进、已归档。归档分栏独立折叠，默认收起，计数采用全部已归档任务总数，不使用完成数／总数，也不按今天日期过滤。
- 归档是任务的独立生命周期状态，与完成状态、任务形态及习惯暂停状态分开。通过新增数据库迁移持久化归档信息，现有任务默认未归档，不修改已发布迁移。
- 便签普通任务的原删除入口改为归档，直接执行；归档任务不进入日常任务查询和完成比例统计，也不因跨日自动归档。归档列表按归档时间从新到旧排列，并使用稳定次序处理相同时间。
- 归档行只显示描述及恢复、删除操作；禁止描述编辑、勾选完成、修改进度、子事项操作、转换、置顶和拖动排序。默认恢复可见，hover或键盘聚焦操作区时显露删除，保持恢复可访问。
- 恢复保留任务标识、描述、形态、完成状态、进度、子事项和置顶信息。采用以下跨日规则：今天任务恢复到恢复当天；多天任务继续沿用多天任务规则，已完成的多天任务以恢复当天作为完成日期，使恢复结果当天可见。该规则属于本规格的补充设计选择。
- 便签归档区的永久删除仅处理已归档任务，删除关联子事项并沿用一次原生确认；取消确认不写入。归档任务的修改限制在共享应用服务中执行，防止其他窗口或迟到的保存覆盖归档状态。
- 习惯生成任务保持现有暂停一次语义，本轮不将暂停转为归档；暂停后当天不重建、次日照常生成。只把便签习惯描述的打开手势从单击改为双击，并更新提示。保留键盘打开习惯页的可访问操作。
- 新增持久化的“显示持续推进”布尔设置，首次使用和缺少字段的旧配置默认为开启；修改后立即同步便签。隐藏分栏仅影响便签展示，主界面的多天任务仍可管理，数据不会转换、删除或归档。
- 隐藏持续推进分栏后，便签任务总数、完成数及总进度只统计这就去做；底部圆环、贴边进度条和胶囊采用相同口径。普通折叠仍计入统计，归档任务始终排除，主界面保留全部日常任务。
- 此开关只控制持续推进，不增加关闭这就去做和已归档的选项。隐藏持续推进后恢复多天任务仍成功，重新开启分栏或打开主界面可查看。
- 设置分成“系统偏好”和“便签偏好”：系统偏好放置开机自启；便签偏好统一放置默认置顶、贴边自动隐藏和显示持续推进。沿用主界面的蓝白风格、细线和留白。本轮只提供这两个分类，后续按实际配置需要再增加主题个性化等分类，不预留空分类。
- 扩展共享数据契约、白名单桌面桥接、IPC校验、共享应用服务及任务仓储。成功写入沿用现有变更广播和重新读取机制，保留保存握手及失败草稿。
- 本轮新增归档入口与手势调整集中于桌面便签；主界面同步排除已归档任务，主界面的现有删除入口行为保持原约定。

## Testing Decisions

- 优先复用现有Electron整体验证入口，贯穿渲染界面、桌面桥接、共享应用服务和真实SQLite，测试用户可见结果，不断言React内部状态、CSS类名或私有方法，也不新增专用测试接口。
- 整体流程覆盖普通今天任务和多天任务归档、数量变化、折叠展开、只读限制、默认恢复与hover删除、恢复、取消及确认永久删除、双窗口同步。
- 交互覆盖习惯任务描述单击不打开、双击只打开一次习惯页，勾选和暂停一次保持正常；键盘可访问恢复、删除和习惯页入口。
- 设置覆盖默认三个分栏、关闭后两个分栏、重新开启恢复原任务、立即同步和重启保留；检查系统偏好、便签偏好的配置归属、分组标题和视觉边界。复用现有便签、习惯Electron验证脚本作为先例。
- 补充现有AppService＋真实SQLite集成测试入口，覆盖归档跨日与重启持久化、恢复保留状态、跨日恢复可见、永久删除关联数据、归档后迟到写入被拒绝。已有任务、多天任务、子事项和习惯测试可作为先例。
- 复用现有桌面偏好读写测试入口，覆盖新字段默认值、旧配置兼容及保存重读。视觉分组使用一次界面检查，不建立重复实现细节的测试。
- 规格阶段不修改实现、不运行功能测试；以上为实现时的验收与测试安排。测试边界已获用户确认。

## Out of Scope

- 主界面新增任务归档管理页、批量归档／恢复／清空、自动清理或过期策略。
- 将完成任务或跨日隐藏的历史任务自动转入归档。
- 改变习惯生成、暂停一次和删除习惯的规则。
- 任意自定义分栏、调整分栏顺序、隐藏其他分栏、标签功能。
- 灵感归档及其他灵感页面改版；已有相关Issue独立推进。
- MCP工具或协议扩展、全局设置页重设计，以及主题个性化等未来设置分类。

## Further Notes

- “已归档任务”指用户主动从日常任务集合移出、仍保留内容且可恢复的任务，与已归档灵感分别管理。
- 本规格将“只显示归档任务数量”理解为默认折叠标题只显示总数，展开后查看只读列表；“二次删除”指从归档中永久删除。
- 默认三个分类指便签任务区的三个分栏，底部任务／灵感新增入口及灵感数量入口继续沿用现有行为。
- 跨日恢复、隐藏分栏时总统计口径、保留习惯暂停一次属于根据现有实现补充的明确边界，可在实施前调整。
