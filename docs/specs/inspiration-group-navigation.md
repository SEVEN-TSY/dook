# 灵感分组导航改版：页内新增、主题管理与归档

状态：2026-11-01产品交互清单及测试边界均已获用户确认；已发布为[GitHub Issue #18](https://github.com/SEVEN-TSY/myTodo/issues/18)，标签为ready-for-agent。本轮仅整理规格，不实施功能。

## Problem Statement

用户已能按日期和主题回顾灵感，但现有展开列表、行内按钮及新增输入方式缺少清晰的浏览层次，视觉样式也不符合用户预期。用户希望在分组导航中专注查看一组内容，围绕主题快速新增和整理灵感，并能将暂时不需要的灵感归档、恢复或永久删除。

用户选择原型C“分组导航”作为布局方向，并确认重做视觉样式。原型中的固定日期、内存示例数据和其他未确认的临时行为不作为正式业务规则。

## Solution

灵感页面内部采用左侧分组导航、右侧灵感列表。保留日期与主题两种视角，每次显示一个分组，日期和主题分别记忆当前打开主界面期间的浏览位置。切换分组时关闭上一组详情，点击当前组灵感的补充操作再打开右侧详情。

新增灵感统一由右侧列表标题行最右侧的“+”触发，在页面内展开输入区；日期下仅今天可新增，主题下各主题及未归类均可新增。在主题下新增自动归入当前主题。另在主题视角左侧导航区域设置新增主题的“+”。

灵感行默认显示归主题文字及图标，hover时展开完整图标操作。归主题使用锚定按钮的Popover，内含支持搜索、创建的多选组合框，勾选即保存。主题可在左侧修改和删除，删除主题不删除灵感。

日期导航末尾提供已归档灵感分组。归档保留内容和关联，已归档记录只提供恢复和永久删除，默认显示恢复；永久删除必须二次确认。所有操作结果在页面上方居中提示。

## User Stories

1. 作为浏览灵感的用户，我希望左侧显示分组导航、右侧显示灵感列表，以便清楚区分选择范围和阅读内容。
2. 作为浏览灵感的用户，我希望保留日期和主题两种视角，以便按时间回顾或围绕主题积累想法。
3. 作为浏览灵感的用户，我希望一次查看一个分组，以便集中阅读当前内容。
4. 作为回顾灵感的用户，我希望日期导航保留今天、前6天和历史灵感，以便沿用已有的时间归集规则。
5. 作为重新打开应用的用户，我希望灵感页默认进入今天，以便快速记录和回顾当天的想法。
6. 作为在两种视角间切换的用户，我希望分别记住选中的分组，以便返回时继续浏览。
7. 作为在两种视角间切换的用户，我希望分别恢复选中的灵感及滚动位置，以便不必重新寻找内容。
8. 作为切换分组的用户，我希望上一组详情关闭，以便右侧详情不会与当前组失去关联。
9. 作为继续完善想法的用户，我希望通过补充操作打开当前灵感详情，以便查看原始想法和历史补充。
10. 作为阅读详情的用户，我希望原始想法完整且只读，以便专注阅读并在列表中统一修改正文。
11. 作为编辑灵感的用户，我希望点击列表正文原地编辑，以便无需进入独立编辑页。
12. 作为浏览灵感的用户，我希望正文沿用最多三行的预览，以便兼顾列表密度和内容识别。
13. 作为补充灵感的用户，我希望在详情中持续追加内容，以便逐步完善同一个想法。
14. 作为主题视角的用户，我希望每条灵感显示完整年月日，以便跨日期阅读时仍能识别记录时间。
15. 作为记录灵感的用户，我希望在右侧分组标题行最右侧看到新增图标，以便在当前浏览上下文中开始记录。
16. 作为日期视角的用户，我希望只有今天显示新增灵感入口，以便避免将新记录误认为过去日期的记录。
17. 作为主题视角的用户，我希望每个主题都能新增灵感，以便围绕当前主题连续记录。
18. 作为暂不分类的用户，我希望在未归类中新增灵感，以便先记下来再整理。
19. 作为主题视角的用户，我希望新增灵感自动归入当前主题，以便无需保存后再手动归集。
20. 作为新增灵感的用户，我希望输入区在页面内临时展开，以便保持浏览上下文。
21. 作为新增灵感的用户，我希望旧的新增入口与输入方式移除，以便页面只有一致的新建流程。
22. 作为连续记录的用户，我希望保存后留在当前分组，以便继续围绕同一方向记录。
23. 作为连续记录的用户，我希望保存后输入框清空并保持展开，以便直接输入下一条灵感。
24. 作为取消新增的用户，我希望通过可见的叉号关闭输入区，以便明确完成取消动作。
25. 作为取消新增的用户，我希望点击叉号后输入立即丢弃、再次打开为空白，以便不需要管理取消的草稿。
26. 作为新增灵感的用户，我希望不使用Esc取消输入，以便取消通过明确的可见入口进行。
27. 作为遇到保存失败的用户，我希望输入仍留在当前输入框，以便重试时无需重新输入。
28. 作为浏览灵感的用户，我希望操作统一使用图标标识，以便减少按钮带来的视觉干扰。
29. 作为整理灵感的用户，我希望默认显示归主题文字及图标，以便随时找到归集入口。
30. 作为操作灵感的用户，我希望hover时展开完整操作，以便在需要时访问补充和归档等动作。
31. 作为浏览灵感的用户，我希望操作展开结束后恢复默认显示，以便列表保持克制。
32. 作为归集灵感的用户，我希望归主题Popover在按钮处展开，以便保留与当前灵感的关系。
33. 作为归集灵感的用户，我希望搜索已有主题，以便主题较多时快速定位。
34. 作为归集灵感的用户，我希望使用多选组合框，以便同一灵感可以属于多个主题。
35. 作为归集灵感的用户，我希望勾选和取消勾选立即保存，以便无需额外确认步骤。
36. 作为建立新主题的用户，我希望在归主题选择器内创建主题，以便整理思路时无需离开当前灵感。
37. 作为建立新主题的用户，我希望创建后自动选中该主题，以便当前灵感立即完成归集。
38. 作为主题管理者，我希望左侧导航区域有独立的新增主题图标，以便创建主题不必先选择一条灵感。
39. 作为主题管理者，我希望在左侧修改主题名称，以便维护长期积累的主题。
40. 作为主题管理者，我希望在左侧删除主题，以便清理不再需要的归集方式。
41. 作为删除主题的用户，我希望删除前看到二次确认及关联灵感数量，以便理解操作影响。
42. 作为删除主题的用户，我希望灵感仍保留，以便删除归集方式不会丢失想法。
43. 作为跨主题整理的用户，我希望删除一个主题不影响其他主题关联，以便继续从其他主题访问同一条灵感。
44. 作为整理灵感的用户，我希望失去全部主题的灵感进入未归类，以便仍可找到尚未分类的记录。
45. 作为整理灵感的用户，我希望将暂不需要的灵感归档，以便从日常列表中移出但保留内容。
46. 作为归档灵感的用户，我希望归档后普通日期和主题列表不再显示该条，以便归档效果在两种视角一致。
47. 作为回顾归档内容的用户，我希望日期导航最后有已归档灵感分组，以便集中查找归档记录。
48. 作为归档灵感的用户，我希望正文、补充、原日期和主题关联都保留，以便日后恢复。
49. 作为浏览已归档灵感的用户，我希望记录只提供恢复和永久删除两个操作，以便归档区的操作边界明确。
50. 作为浏览已归档灵感的用户，我希望默认展示恢复操作，以便方便地重新启用想法。
51. 作为恢复灵感的用户，我希望记录回到原日期和仍存在的原主题，以便恢复原有上下文。
52. 作为清理已归档内容的用户，我希望可以永久删除，以便彻底清理不再需要的记录。
53. 作为永久删除灵感的用户，我希望必须二次确认，以便减少误删。
54. 作为取消删除确认的用户，我希望记录保持不变，以便取消不会产生数据修改。
55. 作为完成操作的用户，我希望页面上部中间显示结果提示，以便知道操作是否成功。
56. 作为完成操作的用户，我希望成功提示约3秒消失，以便不持续遮挡内容。
57. 作为遇到失败的用户，我希望失败提示可关闭，以便阅读错误后继续操作。
58. 作为长期使用的用户，我希望主题、归集、归档、恢复与删除结果在重启后保持，以便整理结果可靠保存。
59. 作为浏览长列表的用户，我希望沿用下滑分页加载，以便内容增加后仍可逐步查看。
60. 作为跨主题编辑的用户，我希望同一条灵感的修改在各处一致，以便无需维护重复内容。
61. 作为偏好清爽界面的用户，我希望字体层级、留白、输入区、图标和Popover重新设计，以便获得统一清晰的阅读和操作体验。

## Implementation Decisions

- 沿用渲染界面、受控桌面桥接、Electron IPC、AppService与SQLite仓储的现有分层；界面不直接操作数据库，不新增常驻后端。
- 在主界面灵感功能内实现分组导航与列表布局，保留应用级导航。详情继续由当前灵感的补充入口打开，切组后清理旧详情关联；视角恢复的选中项必须仍属于恢复后的分组，失效项不能显示为有效选中。
- 日期与主题视角分别保存本次主界面打开期间的导航和阅读状态，不增加跨启动的浏览位置持久化。重新启动进入今天。日期规则使用真实本地自然日，不复用原型固定日期。
- 替换ADR0001及已完成的#14中多组独立展开、主题组默认全折叠的呈现决定，改为单组导航；保留日期范围、历史灵感、记录时间不因修改变化、多主题归集、列表原地编辑、三行预览、右侧只读原始想法与追加补充、下滑分页等已有规则。
- 本轮确认的新视觉覆盖灵感页具体控件样式；在现有蓝白工作界面方向下重新组织字体、间距和控件，不以复用旧CSS作为视觉验收依据。图标具备可访问名称、操作说明与键盘访问能力，继续遵循项目现有可访问性要求。
- 主界面新增灵感入口收敛至列表标题行“+”；主题导航的独立“+”只负责新增主题。页内新增具有可见叉号，取消直接丢弃当前未提交内容。保存成功清空并保持展开；保存失败保留当前输入。不得将取消动作自动保存成真实灵感。
- 主题内新增保存需同时满足新灵感创建和归入当前主题，不出现提示成功但归集失败的结果。日期及未归类新增不强制选择主题。
- 现有主题创建能力依赖已有灵感，需扩展为支持独立新增主题，同时保留从归主题Popover创建并关联当前灵感的流程。具体方法名由实现决定。
- 多选组合框支持搜索已有主题、创建新主题与多个已选项；勾选即保存，创建后自动归集。请求失败必须显示失败结果，不能留下虚假的已保存选中状态。
- 增加主题删除用例，只删除主题及其归集关系，保留灵感与补充；确认提示关联数量应与实际受影响的灵感一致。主题若已删除，恢复归档灵感时不重建该主题，不产生失效关联。
- 扩展灵感持久化状态及查询契约，区分普通灵感与已归档灵感。旧数据迁移后仍为普通灵感，保留已有正文、记录日期、补充和主题关联，不推测缺失的旧日期。
- 普通日期和主题列表排除归档记录；归档区集中查询归档记录。分组内容、分页和相关数量不能因只加载部分数据而遗漏或混入另一状态的记录。跨窗口数据读取与变更通知沿用统一业务入口。
- 归档不删除补充和主题关联，恢复保持原记录时间；永久删除仅从已归档记录的删除操作进入，并在确认后删除记录及所属补充、归集关系。仓储以一致的操作完成相关数据变更。
- 已归档条目不得继续暴露普通正文编辑、追加补充、归主题及再次归档等操作；默认显示恢复，完整操作仅包括恢复和永久删除。内容可供回顾，不引入归档状态下的修改流程。
- 沿用现有注册窗口来源校验与受控确认边界。永久删除确认取消不改数据，确认成功也不能被旧的编辑或追加响应重新创建。保存与归集的过时响应不得覆盖用户较新的状态。
- 操作结果由统一的页面上方居中提示承载：成功提示约3秒消失，失败提示可关闭，失败不丢输入；hover操作区不引入2–3秒的自动收回计时。
- 提交快捷键、导航期间未提交内容的处理、首次进入主题视角的默认组、主题排序、空主题视觉及hover后的文字布局，均未获单独指定。实现需在上述确认规则和现有基础能力内合理处理，不将临时原型行为当作用户已确认要求。

## Testing Decisions

以下测试边界已获用户确认。

- 主要验收边界复用现有真实Electron应用集成入口，贯穿主界面操作、受控桥接、应用服务与真实SQLite；沿用现有灵感及双窗口、重启两阶段验证，不为本轮再创建独立的业务测试接口。
- 只断言用户可观察行为和持久化结果，不断言React私有状态、内部方法调用次数、SQL写法或具体组件拆分。既有依赖多组展开和旧新增入口的断言需随规则更新。
- 从页面操作验证：单组导航、切组关闭详情、两视角分别恢复位置、重启进入今天、主题视角完整日期、按上下文新增、叉号取消后为空白、成功后连续输入、失败保留输入及顶部结果提示。
- 从页面操作验证：hover展开及回到默认操作、按钮锚定Popover、搜索、多选即保存、创建并选中、独立新增主题、改名、删除主题的确认与灵感保留、多主题一致性。
- 从页面操作验证归档、普通分组排除归档、已归档分组可查、归档区仅恢复与永久删除、恢复原日期和原关联、永久删除的确认与取消、删除后不再出现。测试数据使用现有隔离的集成验证数据目录。
- 使用超过一页的数据验证日期、主题和归档列表的下滑加载无遗漏和重复；在主题删除、归档及恢复后验证分组与查询一致，切换视角不得混入旧请求结果。
- 重启后验证主题、归集、归档状态、恢复及永久删除结果；保留现有桌面便签与主界面同步回归，不为本轮重做桌面便签布局。
- 仅对界面入口难以稳定构造的旧库迁移、日期边界、永久删除关联清理及失败场景，补充现有AppService公开接口配合真实SQLite的集成验证，复用现有灵感测试的时钟和旧库构造方式，不对每一层重复写镜像测试。
- 新视觉在真实主界面检查常用宽度与窄窗口，并保留列表、Popover、页内新增、归档区等关键截图；视觉排版采用简短人工检查，交互与数据结果优先自动验证。实施完成时进行类型检查、构建和相关回归。

## Out of Scope

- 本次规格整理不实施界面或持久化代码，不直接将可抛弃原型提升为正式实现，不创建PR或自动部署。
- 桌面便签的布局改版、任务和习惯界面的新增流程改版，以及无关设置和窗口行为调整。
- 灵感转任务、项目创建、需求生成、AI聚类和推荐。
- 主题合并、手动排序、层级主题，以及跨启动保存浏览位置。
- 新增跨会话草稿系统、取消后的草稿恢复、用Esc取消新增。
- 新增MCP业务工具或改变MCP协议；现有服务边界及共享数据的一致性仍需保持。
- 将未讨论的像素值、提交快捷键、首次主题默认项或原型示例状态写成用户已确认要求。

## Further Notes

- 需求来自2026-11-01围绕原型C的交互讨论，用户已统一确认布局、输入、操作、归档、主题管理和反馈清单。先前提出的失败保留输入，指保存失败时文本仍留在当前输入框；主动点击叉号取消仍立即丢弃。
- #14“灵感主页面：按日期与主题归集、原地编辑及下滑分页加载”已关闭，本规格是在已有能力上的后续改版，发布为新的实施Issue，不重新打开旧任务。
- ADR0001中与单组导航冲突的呈现规则需在实施时同步更新，保留原有归集语义。旧规格中主题删除不在范围的限制，由本轮已确认主题管理需求替代。
- 讨论文档和原型用于追溯设计来源；本规格发布后的Issue为本轮实施和验收依据。未知记录日期继续按已有历史灵感规则处理，主题视角不编造年月日。
