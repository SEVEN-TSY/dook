# 一键写日报规格

日期：2026-11-03。2026-11-16按当前实现重写。

现行验收对应[#42](https://github.com/SEVEN-TSY/dook/issues/42)；AI服务配置与场景提示词沿用已完成的#41和#45，提示词设置见[AI场景提示词设置](./ai-scene-prompts.md)。本稿描述当前实现，早期四章节、`requestId` 和“仅本次运行保留草稿”的设计见文末备注。

## 背景

用户已经在DOOK中维护今天任务、多天任务和习惯生成的任务。每天整理日报时，需要重新查看任务状态并组织文字，产生重复劳动。

用户希望在应用中直接得到一份内容有依据、可编辑和可复制的日报。模型输入和输出需要有明确契约，防止遗漏任务、混淆状态、捏造工作成果，或把当前进度写成当天新增进度。

本功能也是通用AI应用集成的首个完整场景：业务层准备事实并验证结果，模型服务负责文字整理，界面提供触发、编辑和复制。

## 方案

主界面任务页提供日报入口，展开列表顶部的日报卡片。生成时先保存相关编辑，由主进程读取本机当天任务，固定快照和编号，读取当前场景提示词，调用默认AI配置生成两节内容。校验来源、子事项和进度后拼装正文，按本地日期保存到本机。正文可原地编辑、自动保存、一键复制和重新生成。桌面便签只提供打开该卡片的导航入口。

## 用户故事

1. 作为用户，我希望在主界面点开日报卡片，并在切换页面后保留展开状态，以便随时查看当天日报。
2. 作为用户，我希望从桌面便签一键打开主界面日报卡片，以便不离开便签开始查看或生成。
3. 作为用户，我希望首次使用时能进入设置添加AI配置，并知道当前使用的是哪个服务商。
4. 作为用户，我希望生成前看到发送范围，并在关闭“显示持续推进”时确认隐藏的多天任务不会出现在日报中。
5. 作为用户，我希望点击生成时先保存会影响日报的编辑，保存失败时保留输入并停止生成。
6. 作为用户，我希望未提交的新增任务草稿保持原样，不进入日报。
7. 作为用户，我希望当天已完成和已归档的任务仍进入日报，以免遗漏成果。
8. 作为用户，我希望习惯生成的任务只汇报一次，未完成的习惯任务不写成完成。
9. 作为用户，我希望未完成的多天任务按当前进度呈现，明日计划按当天净增量给出有依据的目标。
10. 作为用户，我希望生成期间能取消，连续点击不会发起多份并行请求。
11. 作为用户，我希望模型返回格式、来源或进度不一致时得到失败提示，而不是把无效内容当作成功日报。
12. 作为用户，我希望在卡片内直接编辑并自动保存，随时看到最后保存时间，失败时可以重试。
13. 作为用户，我希望一键复制当前编辑后的全文，或重新生成一份。
14. 作为用户，我希望重新生成失败、取消或我中途改过正文时，已有正文不被覆盖。
15. 作为用户，我希望重启应用或进入第二天后仍能看到按原日期保存的正文。
16. 作为用户，我希望联网、鉴权、余额、限流和超时问题有可理解的提示，且不暴露密钥。

## 实现决策

### 1. 入口与卡片

1. 主界面任务页的筛选栏内提供日历图标按钮，悬停和读屏名称为“查看日报”；展开后名称变为“收起日报”，并用 `aria-expanded` 表示状态。归档视图也可使用，点击时切回普通视图再展开。
2. 卡片位于任务列表顶部、新增任务输入之前，与任务卡组同宽，沿用相同背景、弱边界、圆角和间距；卡片随任务列表滚动，窄窗口下操作可换行，编辑和复制入口保持可见和可键盘操作。
3. 卡片标题固定为“日报”，旁边显示正文归属日期。正文是单个可编辑的多行文本域；Enter 换行，输入法组合不受干扰，高度随内容在6至16行之间变化。
4. 卡片元信息包括：本条正文来自多少条任务、生成时使用的服务商名称、最后保存时间（非当天时同时显示日期）和“保存中…”状态。生成时记录的数据截至时间随正文保存，供后续展示和追溯。
5. 操作按钮按状态出现：无正文时为“生成日报”；有正文时为“重新生成”和“复制全文”；生成或取消阶段显示“取消”；缺少默认配置时显示“前往AI设置”；保存失败时显示错误和“重试保存”。空正文禁用复制。
6. 未配置默认AI服务、当天没有可用任务时，卡片内分别显示对应说明。
7. 桌面便签任务页头部提供“打开主界面日报”图标按钮，只负责打开或唤起主界面、切到任务页、展开卡片、滚动定位并聚焦标题，不在便签内生成。沿用便签打开主界面时的贴边收起计时。
8. 重新打开应用后卡片默认收起；展开后显示当天已保存的正文。若当天还没有正文且尚未主动创建任务，则显示前一日的正文及其日期。

### 2. 生成流程

1. 点击生成时要求：没有进行中的请求、已完成准备、当前视图属于当天。重复触发直接拒绝，不合并请求。
2. 先保存本卡片中尚未写入的编辑。
3. 读取准备信息：日期、是否包含多天任务、是否存在被隐藏的多天任务、默认配置指纹与服务商、材料数。与上次准备不一致时提示重新确认，不发起请求。
4. 关闭“显示持续推进”且当天存在按开启口径本应纳入的多天任务时，先显示确认框；用户取消则不调用模型，保留已有正文。确认只对本次请求有效。
5. 主进程向主界面和桌面便签发送保存请求，只等待与本次日报相关的任务描述、子事项和习惯编辑；未显式提交的新增草稿、小记等无关编辑不参与，也不阻塞生成。保存失败、输入法组合未结束或窗口未在10秒内回复时，保留输入并提示涉及的窗口和编辑类型，结束本次生成。
6. 保存完成后再次核对日期、范围、配置和隐藏多天任务；发生变化则回到准备状态，不发起请求。
7. 发请求前最后核对一次，然后读取有效提示词和任务快照，组装消息并发起调用。生成期间正文仍可查看、编辑和复制。
8. 收到有效结果后渲染正文并写入当天记录。若期间用户编辑过日报正文或结果被更新的请求取代，则不采用本次结果，保留现有正文；日期在响应返回后已经变化时报错，同样保留现有正文。已经发生的模型调用只保留调用日志。
9. 保存阶段的取消不再发起请求；联网阶段取消会中止请求。晚到响应不得更新正文。关闭或最小化主界面会取消进行中的生成，编辑照常保存。应用退出前等待进行中的生成结束。
10. 同一时间只保留一个进行中的日报请求；重复触发直接拒绝。

### 3. 日期、范围与材料

日报定义为“生成时当前数据库可知的当天任务状态摘要”，使用主进程时钟和电脑本地日期。生成前固定日期、截至时间和任务快照；数据库读取完成后再发起网络请求，网络请求不占用事务。

生成时按以下口径取材。关闭“显示持续推进”时，主进程在编号、计数和发送前排除全部多天任务，包括当天已完成的多天任务。

| 生成时的任务状态                             | 今日工作内容       | 明日工作计划       |
| -------------------------------------------- | ------------------ | ------------------ |
| 当天已完成、可含已归档的今天任务             | 可用               | 不可用             |
| 当天未完成、未暂停且未归档的今天任务         | 不可用             | 可用               |
| 当天完成的多天任务（含已归档）               | 可用               | 不可用             |
| 当天未完成、未归档的多天任务                 | 可用，可写当前进度 | 可用，可写计划目标 |
| 当天已完成、可含已归档的习惯任务             | 可用               | 不可用             |
| 当天未完成的习惯任务                         | 不可用             | 不可用             |
| 已暂停一次、已删除、其他日期的今天任务       | 不可用             | 不可用             |
| 未完成的已归档任务                           | 不可用             | 不可用             |
| 尚未生成的习惯、小记、主题、未提交的新增草稿 | 不可用             | 不可用             |

- 材料按唯一任务计数，同一任务同时进入两节只算一次；卡片显示的“来自N条任务”取该数。
- 只发送符合范围的任务的未完成子事项正文；子事项不单独计数，也不单独成为材料项。
- AI根据提示词生成明日目标。优先采用任务描述中的明确目标，其次用当前进度加上正的当天净增量。子事项目标最多到总数，手动进度目标最多到100%。缺少这两种依据时只写下一步动作。
- 当天净增量来自进度基线记录：手动进度取净百分点，子事项取新完成减撤销完成的净数；新增或删除子事项引起的比例变化不计为进展。功能上线前的既有任务没有基线，按“无增量”处理。
- 当天没有可用材料时不调用模型，卡片显示空态；只有一节有材料时照常生成。
- 草稿、请求和日志都不包含密钥；模型请求只携带本次材料。

### 4. 输入契约

界面到日报用例：

| 字段             | 约束与含义                                                            |
| ---------------- | --------------------------------------------------------------------- |
| date             | 必填、`YYYY-MM-DD` 格式，且必须等于调用时的本地今天；同时承担跨日保护 |
| includeMultiDay  | 必填布尔值，来自“显示持续推进”设置                                    |
| configuration    | 默认配置指纹或 `null`；用于发现生成期间切换默认配置                   |
| confirmed        | 隐藏多天任务的确认结果，仅对本次请求有效                              |
| editedSinceStart | 生成开始后用户是否编辑过正文，用于丢弃过时结果                        |

界面不能传任务事实、统计、API Key、模型名或系统提示词。所有日报操作仅接受主窗口请求；取消只作用于当前进行中的请求。

日报用例交给模型的材料字段：

| 字段                            | 约束与含义                                                                    |
| ------------------------------- | ----------------------------------------------------------------------------- |
| id                              | 本次请求内从1开始的编号；主进程保留编号到本地任务的映射，请求不携带本地任务ID |
| description                     | 任务原文，单条不超过2000个Unicode码点，不改写数据库原文                       |
| kind                            | `today` 或 `multi-day`                                                        |
| habit                           | 是否由习惯生成，仅说明来源                                                    |
| completed                       | 当前是否完成                                                                  |
| sections                        | 程序给出的可写入章节：`["today"]`、`["tomorrow"]` 或同时两节                  |
| progress                        | 仅未完成多天任务，0至100                                                      |
| todayProgressDelta              | 未完成多天任务的当天净增量，单位为项或百分点；无基线或不适用时为 `null`        |
| subitemTotal / subitemCompleted | 子事项总数和已完成数                                                          |
| subitems                        | 仅未完成子事项，`id` 形如 `1.2`，`description` 同样受单条2000码点限制         |

系统提示词规定输入输出结构、材料来源和进度取值，并要求把任务数据作为材料使用。日报提示词决定标题、措辞、编号、标点和进度写法。有效日报提示词在每次生成时读取。

限额：

| 项目                     | 上限               |
| ------------------------ | ------------------ |
| 任务数                   | 100                |
| 单条任务或子事项描述     | 2000个Unicode码点  |
| 全部任务及子事项描述合计 | 16000个Unicode码点 |
| 请求体                   | 256 KiB            |

任一项超限都在联网前报错，不静默裁剪或丢弃任务。

### 5. 输出契约与校验

模型只返回一个JSON对象，结构为：

```json
{
  "today": {
    "title": "今日工作内容",
    "items": [{ "sourceIds": [1], "subitemIds": [], "text": "修复导出异常" }]
  },
  "tomorrow": { "title": "明日工作计划", "items": [] }
}
```

| 字段             | 约束                                                    |
| ---------------- | ------------------------------------------------------- |
| today / tomorrow | 两个对象都必须存在；只读取这两个字段，其他顶层字段忽略  |
| 每节 title       | 单行、去首尾空白后非空；由模型按写作要求给出            |
| 每节 items       | 最多100条                                               |
| item.text        | 单行、去首尾空白后1至500个Unicode码点。写作要求指定编号时，编号写在条目正文内 |
| item.sourceIds   | 1至100个正整数，必须是本次材料编号                      |
| item.subitemIds  | 可选，最多100个；必须属于本条事项所选来源的未完成子事项 |

校验顺序和规则：

1. 响应状态正常，`finish_reason` 必须为 `stop`，正文非空且不超过64 KiB；外部响应体不超过1 MiB。
2. JSON解析和结构校验；必需字段缺失或类型不符即失败，未知字段忽略。
3. 来源必须存在于本次材料，且该任务的 `sections` 包含当前章节。
4. 同一章节内每个来源只能引用一次；同一任务可以在两节各出现一次。
5. 引用未完成多天任务的事项必须单独一条，不能与其他来源并列。
6. `subitemIds` 必须属于所选来源的未完成子事项，且不重复。
7. 今日进度与快照校验，识别 `(N/M)`、`完成N/M`、`完成N%`、`进度N%`。明日目标由AI按提示词生成，正文保留模型写出的目标。未写进度视为合法。
8. 两节都为空的输出无效；材料全部为习惯任务时给出更具体的提示。
9. 拼装后的正文不超过12000个Unicode码点。

输出不要求覆盖全部输入任务；缺少适用来源时留空 `items`。校验失败不展示为成功日报，不自动再次请求模型修复，也不把原始正文当作可用结果。

### 6. 渲染、保存与错误

- 正文按 `today`、`tomorrow` 顺序拼装。每节先写标题，再逐行写入条目正文，保留模型返回的编号和标点。空的节只保留标题，节与节之间空一行。
- 生成成功后写入本机数据库，记录日期、正文、数据截至时间、最后保存时间和本次范围信息；同一日期只保留一份，重新生成成功后直接覆盖。
- 卡片编辑串行自动保存：停止输入10秒后、失焦、切页、隐藏窗口和正常退出时提交；输入法组合结束后提交。保存成功显示最后保存时间，失败保留当前编辑和上次保存时间，并提供“重试保存”。
- 第二天继续显示前一日的正文和原保存时间；用户当天首次主动创建任务后，卡片切换到当天并显示空态；习惯自动生成任务不触发收起。
- “复制全文”复制 `工作日报｜YYYY-MM-DD` 加当前正文，包括手工修改；正文为空时禁用。
- 失败时保留已有正文：缺少配置、日期变化、无材料、超限、已有请求、鉴权失败、余额不足、限流、网络失败、超时、服务不可用、无效输出和取消都返回可区分的结果，取消不显示为异常。
- 面向用户的提示不包含API Key、认证头、任务原文或完整服务响应，并保留可执行的下一步。与AI相关的错误使用轻提示，其余错误显示在卡片内。

### 7. AI调用与日志

- 复用默认AI配置及其模型、推理强度和凭证，事件为 `daily_report`。请求启用流式JSON Object模式，输出上限8192 Token，单次请求总超时60秒。收到推理或正文片段时更新生成状态，收到结束标记并校验完整响应后显示正文。
- 网络失败、408、429和5xx按800毫秒、2秒退避重试，等待带随机抖动并参考服务端的 `Retry-After`（上限5秒）；累计90秒后不再发起新尝试。鉴权、余额、证书校验和用户取消不重试。
- 每次模型调用写一条 `ai_call_logs` 记录，含配置ID、模型、事件、发起时间、耗时、结果、HTTP状态和Token用量；不记录提示词、任务原文和完整响应。
- 配置元数据保存在 `ai-settings.json`，每条凭证单独加密保存在 `ai-<配置ID>.key`；当前只提供DeepSeek预设，不提供自定义服务地址。

## 测试

自动化测试集中在日报用例的公开接口：使用真实SQLite、真实任务仓储和可控时钟，只在模型传输边界注入响应。

必须覆盖的行为：

1. 当天今天任务、未完成多天任务、当天完成多天任务和已完成归档任务按口径纳入；其他日期、暂停、删除、未完成归档任务不纳入；习惯任务只计一次且只取已完成项。
2. 关闭“显示持续推进”时，两类多天任务都从材料、编号和计数中排除；生成前和保存后各复核一次，确认只对本次请求生效。
3. 材料编号、`sections`、`progress`、`todayProgressDelta` 和子事项过滤正确；删除子事项不产生增量。
4. 空材料、跨日、超限、缺少默认配置、保存失败和已有请求时不调用模型；边界值可以生成。
5. 合法输出通过；非法JSON、空正文、截断、结构错误、未知来源、分类不符、重复来源、非法子事项、多天任务合并、今日进度不一致和超限均拒绝，并保留已有正文。
6. 生成期间修改数据库不改变已固定的材料；取消、晚到响应、跨日和新请求之间互不覆盖。
7. 编辑自动保存、复制前缀、日期切换后的展示与保存、重启后的读取由界面和存储测试覆盖。
8. 通过受控HTTP响应验证模型、推理强度、凭证、JSON模式、超时、重试、响应体上限、错误映射和调用日志；鉴权失败和取消不重试。
9. 使用有效Key手动跑通一次真实生成并核对结果，不进入默认自动测试，不在仓库保存凭证。

## 不在本轮范围

- 周报、月报、任意历史日期生成及历史状态重建。
- 历史时间线浏览、版本管理、导出文件和自动发送。
- 自动创建明日任务，或从旧日报推断未记录的事实。
- 自定义章节结构或顺序、多套模板、聊天改写。
- 多供应商、自定义服务地址和模型参数配置。
