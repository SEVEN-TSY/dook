# 一键写日报：DeepSeek模型API集成规格

日期：2026-11-03。

状态：本地待评审规格；测试边界待确认。本文收敛当前对话，不代表功能已实现。

## Problem Statement

用户已经在myTodo中维护今天任务、多天任务和习惯生成的任务。每天整理日报时，需要重新查看任务状态、统计完成情况并组织文字，产生重复劳动。

用户希望在应用中点击“写日报”，直接获得符合一般工作场景、内容有依据、可以编辑和复制的日报。模型输入和输出需要有明确契约，防止遗漏任务、混淆状态、捏造工作成果，或把当前进度写成当天新增进度。

本次也作为通用AI应用集成的首个完整场景：业务层准备事实并验证结果，模型服务负责文字整理，界面提供触发和编辑能力。

## Solution

在主界面任务页提供“写日报”按钮，在设置页提供DeepSeek API Key配置、替换、清除与连接测试。

用户点击后，应用先完成已有记录的有效编辑保存，再由主进程读取电脑本地当天的任务数据，生成固定快照和统计，通过DeepSeek模型API生成结构化日报。应用验证结果后，在任务页内新增的“日报”卡片中展示内容，支持卡片内原地编辑和一键复制，并提供重新生成及生成期间的取消操作。

默认模板包含“今日完成”“待办与持续推进”“问题与阻塞”“下一步计划”四类内容。首版数据仅来自任务，缺少独立的阻塞和计划来源，因此后两类必须返回空数组，界面隐藏对应空章节。未完成任务只表明当前待完成，不据此推断已经开始、遇到阻塞或明天一定处理。

日报在本次应用运行期间保留为草稿，切换页面后返回任务页仍显示在原卡片中；首版不提供历史日报管理和跨启动恢复。卡片展示、原地编辑和一键复制已由用户明确要求；草稿保留策略、固定模板及下文具体限额属于本规格的首版默认决策。

## User Stories

1. 作为myTodo用户，我希望在主界面任务页点击“写日报”，以便直接整理当天工作。
2. 作为用户，我希望首次使用时能进入设置配置DeepSeek API Key，以便完成模型服务接入。
3. 作为用户，我希望测试连接后得到明确结果，以便判断配置是否可用。
4. 作为用户，我希望更换或清除API Key，以便管理自己的模型服务凭证。
5. 作为用户，我希望点击生成时先保存已有任务的有效编辑，以便日报使用最新内容。
6. 作为用户，我希望保存失败时保留输入并停止生成，以便先解决数据保存问题。
7. 作为用户，我希望未提交的新增任务草稿保持原样，以便自己决定何时创建任务。
8. 作为用户，我希望日报包含今天任务的完成情况，以便汇报已记录的工作。
9. 作为用户，我希望已经完成并归档的当天任务仍进入日报，以免归档操作遗漏成果。
10. 作为用户，我希望习惯生成的任务只统计一次，以免重复汇报同一项工作。
11. 作为用户，我希望已暂停一次的习惯任务不被写成完成，以便日报反映实际记录。
12. 作为用户，我希望日报包含当天完成的多天任务，以便汇报跨日工作的成果。
13. 作为用户，我希望未完成的多天任务按当前状态呈现，以便说明仍待推进的工作。
14. 作为用户，我希望当前进度与当天新增进度区分清楚，以免日报夸大当天产出。
15. 作为用户，我希望日报范围不受列表折叠、归档筛选和显示持续推进设置影响，以便生成口径稳定。
16. 作为用户，我希望看到日报对应日期和数据截至时间，以便判断内容的时效性。
17. 作为用户，我希望生成期间能看到等待状态并取消，以便控制自己的操作。
18. 作为用户，我希望连续点击不会发起多份并行生成，以免重复请求。
19. 作为用户，我希望模型只整理已有事实，以便得到可信的工作描述。
20. 作为用户，我希望缺少问题和计划来源时省略对应章节，以免生成虚构的阻塞和承诺。
21. 作为用户，我希望生成结果中的任务没有遗漏、重复或错误分类，以便快速核对。
22. 作为用户，我希望模型返回格式错误时得到失败提示，以免把无效内容当作成功结果。
23. 作为用户，我希望在任务页的日报卡片内直接编辑文字，以便补充需要由自己判断的内容。
24. 作为用户，我希望通过日报卡片的一键复制按钮复制当前编辑后的全文，以便粘贴到实际汇报渠道。
25. 作为用户，我希望重新生成失败或取消时保留原草稿，以免丢失已经整理的文字。
26. 作为用户，我希望重生成成功后自行确认替换已修改的草稿，以免意外覆盖。
27. 作为用户，我希望联网、鉴权、余额、限流和超时问题有可理解的提示，以便采取下一步操作。
28. 作为用户，我希望任务材料超出首版支持范围时明确提示，以免系统悄悄截断后生成不完整日报。
29. 作为用户，我希望没有可用任务时直接得到提示，以免进行无意义的模型调用。
30. 作为用户，我希望浅色、深色及主题色下均能清楚阅读和操作日报，以便沿用现有使用习惯。
31. 作为用户，我希望日报以任务页内的一张卡片展示，以便在同一页面查看任务和汇报内容。
32. 作为用户，我希望切换其他页面再返回时保留卡片内容和编辑草稿，以免重复生成。

## Implementation Decisions

### 1. 首版流程与界面

1. 入口仅设在主界面任务页标题操作区域，按钮名称为“写日报”；桌面便签本轮不增加入口。
2. 点击后在任务页内容滚动区顶部显示一张“日报”卡片，与现有任务分组卡片纵向排列；首次触发前不占据内容空间。卡片展示日期、数据截至时间、生成状态、日报正文及操作。已有草稿时点击“写日报”滚动定位到卡片，不自动覆盖；由用户点击卡片的“重新生成”发起新请求。首次触发无草稿时直接生成。
3. 缺少凭证时展示“请先配置DeepSeek API Key”及前往设置入口；返回后由用户重新触发，不自动发送任务数据。
4. 发起生成前复用现有保存协调机制，提交两窗口中已有记录的有效编辑；保存失败或输入法组合未结束时停止生成并保留输入。未显式提交的新增任务草稿不参与保存和快照。
5. 保存完成后再核对本地日期。等待期间跨日时拒绝旧日期请求并提示重新生成，避免把旧日期按钮请求绑定到新一天。
6. 快照固定后，生成过程中发生的任务修改不改变本次材料；卡片显示“数据截至HH:mm”，需要最新内容时重新生成。
7. 卡片提供生成中、成功、失败和取消状态；状态与错误显示在卡片内。生成期间禁用重复触发，保留取消入口；每个主窗口最多一个进行中的日报请求。
8. 草稿为卡片内的多行可编辑文本，支持直接原地修改；Enter换行，不触发任务提交或重新生成。编辑立即更新本次运行内草稿，无需额外保存按钮。“一键复制”复制当前编辑区全文，包含用户修改；空白时禁用复制，复制成功使用现有轻量提示，失败保留内容并允许重试。结构化结果、来源关系与统计用于生成验收和初始渲染；用户手动修改后不再声称文本通过了模型输出契约校验。
9. 已修改的草稿在重生成成功后通过应用内确认决定是否替换；拒绝替换时保留原草稿。失败、取消和过时结果均不能覆盖原草稿。
10. 卡片随任务页展示，首版不提供独立弹窗、抽屉或详情页，也不增加卡片关闭入口。切换页面或任务归档标签时保留日报草稿；切换页面不中断生成，返回后展示最新状态。主窗口隐藏时取消请求并保留本次运行内草稿；退出后不恢复。卡片明确提示草稿未持久保存。
11. 本地日期变化后保留旧草稿及其原始日期；用户显式发起当天生成时才准备新快照。取消、窗口隐藏与请求版本共同防止晚到响应覆盖当前状态。
12. 复用项目现有基础控件、应用内确认、错误提示和主题变量，不引入独立视觉体系。首次使用说明任务材料将发送至DeepSeek，用户点击生成即发起请求，不增加逐次确认。
13. 卡片沿用现有任务分组的轻背景、弱边界、圆角及间距，宽度与任务卡组对齐。页头和筛选栏保持现有固定布局，日报卡片与任务卡组共同滚动；长日报在卡片内完整换行展示，避免横向溢出。窄窗口下操作可换行，编辑和复制入口保持可见、可键盘操作。

### 2. 业务分层与共用逻辑

- 主进程的日报生成用例负责：核对日期、读取事实、建立快照、计算统计、验证限额、调用注入的文本生成依赖、验证输出并返回结果。
- 任务仓储提供按日报口径读取任务的专用查询；不通过界面当前列表、渲染层筛选结果或读取所有历史归档后拼装日报。
- DeepSeek适配器负责固定服务地址、认证、请求参数、HTTP响应解析、超时和取消。业务核心不导入Electron、React或模型SDK。
- 凭证读写和系统加密留在主进程的桌面适配层，由组合入口注入依赖。界面只通过白名单DesktopApi和IPC使用固定能力，不提交任意地址、SQL、模型指令或工具定义。
- 渲染层负责保存协调、交互状态、草稿编辑和复制；日期、事实范围、统计与结果有效性由主进程决定。
- 首版只接DeepSeek，不建设多供应商平台，不开发Agent运行循环、Function Calling或MCP工具。以后增加其他入口时，应调用同一日报用例或复用其事实和验证规则。
- 不新增日报持久化表，不修改任务完成、归档、恢复和习惯生成规则。新增查询能力与独立加密凭证存储即可支持本轮功能。

### 3. 日期、范围与统计口径

日报定义为“当天生成时，当前数据库可知的任务状态摘要”。使用主进程注入时钟与电脑本地日期，生成网络请求前固定一次日期、截至时间和数据快照。数据库读取在一致性读事务内完成，网络请求不占用事务。

| 数据类型与状态 | 首版处理 |
| --- | --- |
| 所属日期为当天、未暂停的今天任务，当前已完成 | 进入completed，包含已归档任务 |
| 所属日期为当天、未暂停且未归档的今天任务，当前未完成 | 进入ongoing，文字只能表述待完成 |
| 已归档且未完成的今天任务 | 排除 |
| 当前已完成且完成日期为当天的多天任务 | 进入completed，包含已归档任务 |
| 当前未完成且未归档的多天任务 | 进入ongoing，标注当前进度；不推断今天是否推进 |
| 已归档且未完成的多天任务 | 排除 |
| 习惯生成的今天任务 | 按对应今天任务计入一次，仅携带习惯来源标识，不再次统计习惯定义 |
| 已暂停一次、永久删除、其他日期的今天任务 | 排除 |
| 尚未到生成时间、尚未生成的习惯任务 | 排除，不为写日报额外创建任务 |
| 小记、主题、历史补充和未提交新增草稿 | 首版不读取、不发送 |

统计由程序计算，定义为纳入快照的任务总数、已完成数、未完成数及其中习惯任务数。满足“总数=已完成数+未完成数”，任务按稳定标识去重；日报统计与日常列表的归档排除口径不同，需要在卡片说明“包含当天已完成并归档的任务”。首版不显示完成率，避免与界面日常统计混淆。

子事项不单独作为日报事项、不额外发送其正文；只读取所属任务的当前完成状态与当前进度。多天任务进度使用现有业务规则的结果。

现有记录缺少完整的完成事件和每日进度快照。恢复任务可能更新所属日期或完成日期，永久删除与删除习惯也可能移除当天任务。因此不能保证还原真实的完成时刻、当天进度增量或已删除内容。创建时间不用于猜测上述事实。本轮不增加事件记录机制，也不支持历史日期生成。

### 4. 输入契约

输入、模型材料与模型输出均使用严格运行时Schema验证，拒绝未知字段；采用项目已有验证库，避免仅依赖TypeScript静态类型。

**界面到日报用例：**

| 字段 | 约束与含义 |
| --- | --- |
| date | 必填、有效的YYYY-MM-DD本地日期，必须等于调用时主进程的本地今天；同时承担跨日保护 |
| requestId | 必填、非空且长度不超过64的调用标识，用于取消、请求关联和丢弃晚到结果，不作为持久幂等承诺 |

界面不能传任务事实、统计、API Key、模型名或系统提示词。取消仅能操作所属窗口创建的进行中请求。重试使用新requestId并读取新快照。

**日报用例到模型的材料：**

| 字段 | 约束与含义 |
| --- | --- |
| schemaVersion | 固定为1 |
| date | 经主进程确认的本地日期 |
| asOf | 带时区信息的有效ISO时间，表示本次快照截至时间 |
| facts | 1至100项任务事实，id唯一；不包含密钥和内部配置 |
| facts[].id | 非空任务稳定标识，长度不超过128 |
| facts[].category | completed或ongoing，由程序根据快照确定 |
| facts[].kind | today或multi-day，沿用任务形态 |
| facts[].text | 非空任务描述，首尾去空白后1至2000个Unicode码点，不改写数据库原文 |
| facts[].currentProgress | 仅多天任务提供，使用现有业务计算结果，范围0至100 |
| facts[].fromHabit | 布尔值，用于说明来源，不生成第二条事项 |

首版不接收用户额外的阻塞、计划或自定义提示词；因此输入没有这两类事实。固定系统指令明确任务描述仅是待整理数据，描述中夹带的命令不能改变任务和输出规则。

输入限额：最多100项任务，所有任务描述合计不超过16000个Unicode码点，最终请求体不超过256KiB。任何单项或总量超过限制都在联网前返回明确的超限失败，不静默裁剪、丢弃任务或仅取前若干项。无任务时返回无材料结果，不调用模型。以上为首版产品限额，与模型服务上下文上限分开管理。

### 5. 模型输出契约与验证

模型仅返回一个JSON对象。顶层固定为completed、ongoing、blockers、nextSteps四个必填数组，拒绝额外字段；禁止Markdown代码围栏、解释前言和JSON之外的文字。

| 字段 | 约束与含义 |
| --- | --- |
| completed | 0至100项，只引用输入category为completed的任务 |
| ongoing | 0至100项，只引用输入category为ongoing的任务 |
| blockers | 首版必须为空数组 |
| nextSteps | 首版必须为空数组 |
| 各非空事项的text | 首尾去空白后1至500个Unicode码点，普通中文文本；不含日期标题、统计汇总或来源标识 |
| 各非空事项的sourceIds | 1至100个不重复任务id，全部存在于本次快照，且符合所在数组分类 |

所有事项合计最多100项，所有text合计不超过12000个Unicode码点。单个任务只能出现在一条事项的sourceIds中；completed与ongoing合起来必须恰好覆盖全部输入任务。允许把同类相关任务合并成一条描述，但必须列出全部来源；不允许跨状态合并。相同任务描述、不同任务id不能被直接去重丢失。

验证顺序：HTTP结果与服务返回状态→响应体大小→完成原因与消息正文→JSON解析→严格Schema→来源存在性→分类一致性→完整覆盖与去重→输出总量。外部响应体最多1MiB，待解析的模型正文最多64KiB；超过任一限制即失败。仅正常结束且正文有效的结果能通过，截断、空白、空正文、工具调用、缺少必需字段和业务约束不符均返回失败。

任务完成与归档状态、日期、当前进度、截至时间和汇总数量均由程序保管；模型不能更改这些值。进度数值与来源映射可由程序用于初始渲染，模型不得推测新增比例、耗时、成果数量或未记录的结论。

生成指令要求：忠于原文、简洁整理、保留专有名称与明确成果；未完成今天任务用“待完成”等中性表述；持续推进仅描述当前状态；不推断开始时间、完成时刻、今日进展、阻塞原因、下一步承诺或价值收益。

结构和来源关联可以严格验证，但合法sourceIds不代表自然语言一定忠实；语义忠实度依靠固定样例评估、清晰提示和用户最终编辑核对。测试不得声称Schema能证明语义真实性。

校验失败不展示为成功日报，不把原始模型正文直接作为可用结果，也不自动再请求模型修复。

### 6. 用例输出、渲染与错误契约

用例成功结果包含：requestId、schemaVersion、date、asOf、程序计算的统计、通过校验的四个章节及来源关联。API Key和原始服务响应不进入成功结果。

初始日报由程序统一拼装：标题“工作日报｜YYYY-MM-DD”、数据截至时间、任务统计、非空章节及事项。ongoing显示为“待办与持续推进”；其中今天任务不能被统一称为“进行中”。多天任务当前进度由程序依据来源事实补充，不展示为今日增量。初始文本不展示内部任务id；卡片状态可以保留来源关联用于定位和核对，首版不要求来源跳转界面。

继续使用现有ApiResult包装跨进程结果。日报业务返回可区分的成功或失败结果；失败至少包含稳定错误码、面向用户的信息及是否允许手动重试。取消属于单独的用户操作结果，不显示为服务异常。非法IPC参数和来源继续由现有边界拒绝。

错误分类覆盖：未配置凭证、日期变化、保存失败、没有材料、材料超限、已有请求进行中、鉴权失败、额度或余额不足、限流、网络失败、超时、服务不可用、无效模型输出、取消。面向用户的信息不包含API Key、完整认证头或原始服务响应；保留可以采取的下一步操作。

### 7. DeepSeek接入与凭证

1. 使用官方固定地址的Chat Completions接口，模型固定为deepseek-flash，显式关闭思考，非流式请求，启用JSON Object响应模式。系统指令同步要求JSON和具体字段；JSON模式仅作为格式辅助，应用仍完整执行自身Schema及业务校验。接口事实依据[DeepSeek首次调用API](https://api-docs.deepseek.com/zh-cn/)及[Chat Completions文档](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)，核对日期为2026-11-03。
2. 输出token上限首版设置为8192，单次请求总超时60秒；不进行自动网络重试和自动模型修复。用户可修改配置后手动重试，重试重新建立当天快照。
3. 设置页API Key采用密码输入；保存成功后清空输入框，再次打开只显示已配置状态，不回显明文。支持替换和清除，保存失败保留用户本次输入以供重试。
4. API Key经受控IPC提交至主进程，以操作系统加密能力加密后保存到应用数据目录。使用当前Electron支持的异步safeStorage能力；加密不可用时明确失败，不回退明文存储。依据[Electron safeStorage文档](https://www.electronjs.org/docs/latest/api/safe-storage)，核对日期为2026-11-03。
5. 连接测试使用固定、极短且不含用户任务的材料验证当前已保存凭证和所选模型调用能力；明确可能产生少量API费用。测试不写入日报草稿，也不要求测试通过才能保存凭证。
6. 仅发送本次日报所需字段；不发送小记、完整数据库、应用诊断或其他历史内容。日志和错误信息不输出密钥、任务原文及完整模型响应。
7. 本轮不开放自定义服务地址、模型选择、采样参数、提示词编辑、流式输出或聊天入口。底层采用直接HTTP或轻量客户端即可，无需引入Agent框架。

## Testing Decisions

### 测试边界提案

主要业务测试集中在“日报生成用例”的公开接口：使用真实SQLite、真实任务仓储及现有任务业务接口准备数据，注入可控时钟，并只在外部模型传输边界提供可控响应。一次调用验证事实选择、统计、结构校验及返回行为，不对内部函数调用顺序、提示词整段文本或模块拆分写镜像测试。

复用现有任务、多天任务、归档与习惯测试中“AppService公开接口+真实SQLite+可控日期”的方式。适配器另用受控HTTP传输验证协议；少量真实Electron场景覆盖按钮至主进程再到编辑区的链路。业务规则集中在主边界验证，界面检查避免重复全部组合。

按to-spec技能要求，该测试边界需要用户确认；在确认前作为可评审提案保存在本地，不标注ready-for-agent。

### 必要测试行为

1. 当天今天任务、未完成多天任务、当天完成多天任务及已完成归档任务按口径纳入；历史任务、暂停任务、未完成归档任务和删除任务不纳入。
2. 习惯来源任务只计一次，尚未生成的习惯不会为日报额外创建任务；数量满足统计恒等式。
3. 列表筛选、折叠与显示持续推进设置不影响同一快照范围。
4. 恢复任务沿用当前日期规则；测试明确验证当前状态摘要的限制，避免宣称历史重建。
5. 多天任务保留当前进度，不制造当天增量；子事项不重复计数。
6. 空材料、过期日期、无效输入和限额超出时不调用模型；边界值可以生成。
7. 合法输出通过；非法JSON、空正文、截断、额外字段、字段类型错误、未知来源、错误分类、重复来源、遗漏来源、超限、非空阻塞及计划均拒绝。
8. 生成期间修改数据库不会改变已固定的材料和返回统计；取消、晚到响应和新请求之间互不覆盖。
9. DeepSeek请求使用指定模型、非流式、关闭思考、JSON模式及认证；鉴权、额度、限流、网络、超时、响应体超限和异常结束映射为预期错误。用可控服务响应测试，不依赖线上API稳定性。
10. 凭证保存、替换、清除和读取配置状态正常；加密不可用时不写明文。错误与日志不泄露密钥。
11. Electron功能检查覆盖：任务页内生成并显示日报卡片、缺少凭证跳转、生成前等待已有编辑保存、保存失败阻止生成、未提交新增草稿保留、生成中取消、错误后重试、卡片原地编辑及Enter换行、一键复制当前修改后的全文、复制失败保留内容、重生成覆盖确认、切页与归档标签切换保留草稿、窗口隐藏取消、长内容共同滚动、窄窗口及主题适配。
12. 少量固定材料评估自然语言：已完成任务、未完成任务、零进度多天任务、同名不同任务、描述含伪指令、缺少阻塞及计划。核对没有凭空成果、完成时间和今日进度；不要求模型逐字输出固定句子。
13. 实现完成时，在配置有效凭证的开发环境手动跑通一次真实DeepSeek生成并核对结果。该检查不进入默认自动测试，不在仓库保存凭证。

测试通过的核心标准是用户可观察行为和数据契约成立；不以具体函数名、文件划分、某条SQL文本或生成文案逐字一致作为验收依据。

## Out of Scope

- Codex、WorkBuddy等外部Agent接入，以及新增或修改MCP工具。
- 应用启动Agent IDE、Agent SDK、工具调用、自主规划和多轮Agent工作流。

- 每日进度快照、任务操作日志或完成事件的数据模型改造。
- 桌面便签写日报入口、定时自动生成、流式展示和后台自动重试。
