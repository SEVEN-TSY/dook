## Problem Statement

应用当前只有主题色配置，主界面、设置和桌面便签使用浅色表面。用户在夜间使用时无法选择协调的深色外观，也无法随Windows系统外观自动切换。单独压暗背景无法满足用户对整体观感的要求，文字、控件、浮层及贴边形态需要共同适配。

原“灵感”定位偏向希望后续探索的构想，无法完整表达用户随时随地记录想法和小事备忘的需求。用户希望统一改称“小记”，继续作为文字记录使用，保留现有业务逻辑。

便签目前切换新增类别只改变输入框，上方始终显示任务。用户在新增小记时无法直接查看当天已记下的内容，希望列表随类别切换，并以类似手机桌面的横向动画表达两个页面的关系。

## Solution

在设置的个性化区域增加“随系统／浅色／深色”，默认随系统。深色外观采用中性黑灰主题，完整适配应用各表面、文字和交互状态；保留用户选择的主题色，所有窗口立即同步。

将用户可见的“灵感”业务名称统一为“小记”，定位为随时随地记录想法和小事备忘。名称和定位调整沿用现有数据及规则，不改变正文、日期、主题、补充和归档逻辑，也不接管已完成的主界面管理调整。

便签切换底部新增类别时，上方同步切换任务和当天小记列表。切到小记时任务向左滑出、小记从右侧向左滑入；切回时整体向右。小记页头显示“小记”和条数，行样式沿用便签任务，仅提供归档。工具栏、底部入口及双圆环固定，窗口尺寸保持稳定。

## User Stories

1. 作为夜间使用应用的用户，我希望在设置中选择外观，以便在不同环境下舒适查看内容。
2. 作为首次使用应用的用户，我希望外观默认随系统，以便应用与Windows保持一致。
3. 作为跟随系统的用户，我希望系统外观变化后应用立即同步，以便无需重启或手动切换。
4. 作为偏好浅色的用户，我希望可以固定浅色外观，以便系统变化时仍保持自己的选择。
5. 作为偏好深色的用户，我希望可以固定深色外观，以便持续使用夜间视觉。
6. 作为重新启动应用的用户，我希望外观选择被记住，以便无需重复配置。
7. 作为使用旧配置的用户，我希望缺少外观选项时自动采用随系统，以便直接获得合理默认值。
8. 作为使用多个窗口的用户，我希望主界面、设置和便签采用相同外观，以便视觉保持一致。
9. 作为使用贴边便签的用户，我希望细条和统计胶囊也适配深色，以便收起和展开形态保持协调。
10. 作为关注观感的用户，我希望深色外观采用黑灰背景与清楚的表面层次，以便夜间模式仍然美观。
11. 作为查看内容的用户，我希望正文、辅助文字、边界和图标在深色下清晰，以便轻松辨认内容。
12. 作为操作界面的用户，我希望输入、菜单、浮层、弹窗以及悬停、焦点、选中和错误状态均适配外观，以便正常操作。
13. 作为选择了主题色的用户，我希望切换外观后保留主题色，以便继续使用自己的个性化设置。
14. 作为随手记录的用户，我希望原灵感业务统一叫作小记，以便理解它可以记录想法和小事备忘。
15. 作为快速记录的用户，我希望小记可以只是一句文字，以便无需先整理成完整任务。
16. 作为已有记录的用户，我希望更名后原有正文、日期和主题继续保留，以便继续查找和整理内容。
17. 作为已有补充或归档记录的用户，我希望更名后这些内容和能力继续保留，以便已有数据不受影响。
18. 作为查看主界面的用户，我希望现有小记管理交互保持，以便本轮调整不打断已经形成的使用方式。
19. 作为便签用户，我希望选择小记新增类别时上方立即显示小记列表，以便边查看边记录。
20. 作为便签用户，我希望切换类别无需先提交一条记录，以便先浏览对应内容。
21. 作为当天记录的用户，我希望便签只显示今天的小记，以便聚焦当天备忘。
22. 作为查看小记的用户，我希望页头显示“小记”和条数，以便知道当前页面和内容数量。
23. 作为查看长小记的用户，我希望条目采用任务列表相同的紧凑呈现，以便便签保持一致的密度。
24. 作为查看长正文的用户，我希望单行省略后可以通过悬停查看全文，以便兼顾紧凑布局和阅读。
25. 作为整理当天小记的用户，我希望可以直接归档条目，以便移出日常列表并保留内容。
26. 作为归档小记的用户，我希望列表和数量同步更新，以便确认操作结果。
27. 作为使用文字备忘的用户，我希望便签小记列表只提供归档，以便保持简单的查看和整理方式。
28. 作为从任务切到小记的用户，我希望任务向左滑出、小记从右向左滑入，以便直观看到页面切换。
29. 作为返回任务的用户，我希望小记向右滑出、任务从左向右滑入，以便方向关系连续一致。
30. 作为切换页面的用户，我希望顶部工具和底部新增入口保持固定，以便操作位置稳定。
31. 作为使用双圆环的用户，我希望两个圆环保持固定且继续打开主界面对应页面，以便沿用已有入口。
32. 作为切换页面的用户，我希望便签窗口尺寸保持稳定，以便桌面布局不跳动。
33. 作为浏览长列表的用户，我希望任务和小记分别保留滚动位置，以便来回切换后继续阅读。
34. 作为使用鼠标的用户，我希望通过现有类别图标切页，以便无需学习额外手势。
35. 作为正在输入的用户，我希望切换类别前沿用原有保存规则，以便草稿得到正确处理。
36. 作为遇到保存失败的用户，我希望草稿保留且页面不切走，以便直接重试。
37. 作为连续新增的用户，我希望保存、清空、焦点和失焦收起继续按原有方式工作，以便保持快速记录节奏。
38. 作为使用中文输入法的用户，我希望选字和切页继续受现有保存保护，以便不会误提交或丢失输入。
39. 作为暂时隐藏便签的用户，我希望重新唤出时保留当前页面，以便继续刚才的记录。
40. 作为重启应用的用户，我希望便签默认进入任务页，以便先看到待办事项。
41. 作为应用跨日运行的用户，我希望小记页自动展示新一天的内容，以便“今天”的范围始终正确。
42. 作为同时使用主界面和便签的用户，我希望新增、归档及数量变化跨窗口同步，以便看到一致的记录。

## Implementation Decisions

- 本次交付仅为规格综合与Issue发布，不实施功能。后续执行该规格时，改动范围为外观设置、视觉适配、业务文案和便签视图编排；用户要求保留既有小记业务逻辑。
- 外观配置纳入现有个性化设置及桌面偏好持久化，表达随系统、浅色、深色三种用户意图。旧偏好缺失该项时默认随系统；重启恢复选择。固定浅色或深色时，不被系统变化覆盖。
- 复用现有受控设置桥接、主进程偏好及窗口状态同步机制。系统外观解析及变化订阅在平台边界完成，所有窗口使用一致的生效外观。无需建立独立服务或改变业务数据库。
- 深色使用中性黑灰背景及表面层次；覆盖主界面、设置、便签、细条、胶囊、输入、滚动条、菜单、浮层、应用内确认和交互状态。保留现有字体、布局密度、圆角及主题色选择，统一调整颜色职责，避免零散背景替换留下浅色控件。
- 主题色继续作为独立的个性化选项。黑灰表面与正文、弱边界、悬停、焦点、禁用及错误状态需要共同检查可读性和协调性；具体色值交由实施时的视觉检查确定，未讨论的像素值不作为用户逐项确认的决定。
- 用户可见业务名称、导航、提示和说明统一使用“小记”，含义为随手记录想法和小事备忘。内部标识、既有接口和数据表可保留原名称，无需为更名迁移已有数据或修改协议。
- 既有正文编辑、日期归属、多主题归集、补充数据及接口、归档恢复与永久删除规则保持不变。小记与任务继续保持各自语义，不增加完成状态或提醒。
- 便签复用既有小记查询、创建、归档及变更订阅能力，按现有电脑本地日期规则显示当天未归档记录，沿用记录时间倒序。历史和无日期记录不进入当天列表；日期归属不因编辑或补充改变。
- 小记页头显示“小记”和当天可见条数。条目沿用便签任务的48px行高、字体、留白、单行省略及全文悬停提示；不呈现任务完成勾选，唯一行内操作为归档叉号。归档复用原有直接归档用例，不新增确认步骤。
- 用户已明确取消小记置顶；不增加置顶字段、接口、排序分区或按钮。便签列表也不新增正文编辑、主题归集、补充、恢复或永久删除入口，既有主界面管理能力保持。
- 底部新增类别同时决定当前列表和输入类别。切换前继续提交原类别的有效草稿；输入法组合输入未结束或保存失败时保留草稿及原页面。不得绕开既有保存屏障或改变连续新增、清除、失焦收起及失败反馈规则。
- 类别切换由现有图标触发，无需先新增内容。任务到小记时整体向左移动，小记到任务时整体向右移动；仅中间列表视口作横向过渡，顶部工具及底部新增入口和双圆环位置固定。标题与条数随当前页面更新。
- 两页共用稳定的列表可视区域，切页不改变原生窗口尺寸；长列表独立滚动并各自保留滚动位置。沿用现有动画基础及减少动态效果规范，具体动画时长由实施阶段确定。
- 不增加鼠标拖动、触控板或触屏切页手势。顶部窗口置顶和任务已有置顶能力保持原状，取消的是小记条目置顶。
- 两个圆环继续承担原有统计及主界面导航职责。任务环及贴边统计继续只计算任务；小记环继续按当天未归档新增数量统计，沿用5条满环目标及现有反馈，不借业务更名改变计数规则。
- 当前进程中隐藏、唤出便签保留当前页；应用重新启动默认任务页，不新增跨启动的浏览页持久化。跨日时小记页更新到新一天，主界面新增、归档、恢复等变更按既有通知同步列表及数量。
- 遵循既有渲染层、受控桌面桥接、应用服务、存储分层。新增外观偏好属于配置变化；小记列表使用现有业务入口，不为本轮引入业务模型、数据库结构或MCP协议变更。

## Testing Decisions

以下验收方案基于现有验证入口综合，是后续实施建议；本次没有另开测试访谈，也不将这些细节表述为用户逐项确认。

- 好的测试断言用户可见行为和持久化结果，不绑定React私有状态、组件拆分、内部调用次数、CSS类名或SQL写法。可逆样式改动使用简短视觉检查，不建立镜像测试。
- 主要验收边界使用现有真实Electron界面，经桌面桥接、应用服务到真实SQLite；复用既有隔离数据目录、双窗口操作及首次操作／重启两阶段验证。无需新建独立测试API或另一套测试基础设施。
- 已有桌面设置、主题色、便签归档、小记主界面分页及双窗口同步验证提供先例。扩展现有Electron验证覆盖外观选择、系统变化、便签列表和横向切页；仅在操作系统外观来源及时钟等外部边界注入可控条件，不替换业务链路。
- 外观验证覆盖旧配置默认随系统、系统浅深切换立即生效、固定模式不随系统改变、配置重启恢复、双窗口一致及主题色选择保留。
- 对主界面、设置、便签、细条和胶囊作浅色及黑灰深色视觉检查；抽查输入、Popover、菜单、确认弹窗、错误、禁用、悬停和键盘焦点，包含现有预设与自定义主题色的代表场景。重点检查整体层次和残留浅底，避免为每个颜色编写实现镜像断言。
- 小记验证覆盖今天、历史、无日期和已归档记录的范围，列表条数与圆环一致，归档后列表及主界面同步更新；验证新增连续输入、失焦保存、输入法保护及失败保留草稿沿用现有结果。
- 界面验证切换图标立即改变列表和输入类别，两个方向正确，顶部与底部操作保持稳定，窗口尺寸不变，长列表各自恢复滚动位置。保存失败或组合输入未结束时，不将页面切走。
- 验证便签小记只有归档行操作，无置顶、完成勾选或编辑入口；正文单行省略且可查看全文提示。验证两个圆环导航职责、任务完成统计及5条满环规则保持原状。
- 验证隐藏后恢复当前页、重启默认任务页、跨日显示新一天，以及主界面修改引起的双窗口一致性。复用已有小记业务集成验证保障日期、主题、补充及归档数据保留，不为名称变化重复构造每层测试。
- 后续实施运行类型检查、构建及受影响的现有回归；界面无法稳定构造的业务失败与数据保留场景，优先复用现有应用服务公开接口及真实SQLite验证。当前规格发布不运行应用测试，也不声明功能验收通过。

## Out of Scope

- 本次规格发布不实施业务或界面代码，不创建PR或部署。
- 改变现有小记正文、主题、日期、补充、归档、恢复和删除逻辑；新增或迁移小记业务数据库结构。
- 小记条目置顶、拖动排序、完成勾选、到时提醒、转任务或AI整理能力。
- 在便签小记列表新增编辑、详情、主题整理、补充、恢复或永久删除入口。
- 重新设计主界面小记管理、恢复已移除的详情和补充界面，或接管其他任务的逻辑调整。
- 鼠标拖动、触控板或触屏切页手势，以及跨启动记忆便签当前页面或滚动位置。
- 改变任务完成统计、小记5条满环目标、圆环主界面入口及贴边收起交互。
- 为名称统一重命名全部内部开发标识、改造业务接口或修改MCP协议。
- 将尚未讨论的精确色值、空状态文案或动画毫秒数当作用户已确认的固定条件。

## Further Notes

- 需求来自2026-11-02本聊天的逐轮讨论；用户最终要求“这轮先不碰逻辑”。本轮交付正式规格及Issue，后续实现继续受保留既有业务逻辑的边界约束。
- 用户最初提到便签小记置顶，后明确取消；最终唯一行内操作为归档。滑动方向以用户纠正后的任务到小记向左、返回向右为准。
- ADR0001中的旧“灵感”定位已追加业务命名更新，领域术语统一为“小记”。日期和主题能力继续沿用既有决定；未新增架构ADR。
- [Issue #27](https://github.com/SEVEN-TSY/dook/issues/27)已关闭，当前代码已包含其主界面调整。本规格在该基线上增加外观和便签列表，保留默认主题／未归类、正文两行、多主题归集及移除补充界面等现有行为。
- Issue #27曾把便签正文列表排除在自身范围之外；本规格明确增加该列表，不应将旧范围限制误认为永久禁止。
- 当前实现尚无外观三态及便签小记正文列表。当前工作区含其他任务改动，规格发布期间仅维护本轮文档；后续实现应基于最新代码接入，避免覆盖并行工作。
