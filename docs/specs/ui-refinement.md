## Problem Statement

用户在整理灵感及操作应用时遇到多处界面不一致：返回列表入口过小，删除确认使用系统弹窗而与应用视觉脱节，灵感输入缺少清除叉号，主题编辑无法通过点击外部取消。灵感详情及补充内容增加了当前浏览流程的负担，默认时间视角和主题新增入口也不符合用户围绕主题整理想法的习惯。

归集主题的Popover较宽，与触发按钮的展开关系不清晰，缺少明确关闭入口，创建并归集的文字按钮过重。用户希望调整这些操作，同时保留现有提交逻辑、多主题归集及已有数据。

## Solution

统一返回列表入口和应用内删除确认；为灵感输入补齐清除操作，保持提交方式，主界面正文最多两行。便签新增灵感与便签新增任务使用一致的单行输入形式。

灵感页面移除详情及补充入口，默认按主题打开未归类；新建主题仅用未归类分组项右侧的加号表示，新建及修改主题点击外部取消。主题归集继续多选，Popover缩窄、增加关闭叉号，并体现与行按钮的展开关系；已有主题勾选后保持开启，新主题通过输入框右侧回车图标创建并归集，成功后关闭。

## User Stories

1. 作为查看任务详情的用户，我希望返回列表入口足够容易点击，以便快速回到列表。
2. 作为在不同页面操作的用户，我希望同类返回入口使用统一样式，以便凭相同习惯操作。
3. 作为查看详情的用户，我希望返回入口包含左箭头和返回列表文字，以便理解按钮用途。
4. 作为键盘用户，我希望返回入口具有清楚的焦点和悬停状态，以便识别当前操作位置。
5. 作为编辑内容的用户，我希望返回时保留现有保存和失败处理，以便不会丢失修改。
6. 作为删除内容的用户，我希望确认弹窗符合应用视觉，以便操作过程保持一致。
7. 作为使用不同窗口的用户，我希望现有删除确认统一使用应用内弹窗，以便无需适应不同风格。
8. 作为取消删除的用户，我希望取消后数据保持原状，以便安全返回当前内容。
9. 作为确认删除的用户，我希望确认后才执行删除，以便理解并控制操作结果。
10. 作为删除主题的用户，我希望看到关联灵感数量，以便知道影响范围。
11. 作为删除主题的用户，我希望灵感继续保留，以便只清理主题而不丢失内容。
12. 作为永久删除归档内容的用户，我希望弹窗说明不可恢复及受影响内容，以便明确后果。
13. 作为归档任务或暂停习惯任务的用户，我希望保留现有直接操作，以便不增加额外确认。
14. 作为新增灵感的用户，我希望输入有内容时显示清除叉号，以便一键重新输入。
15. 作为原地编辑灵感的用户，我希望编辑框也提供清除叉号，以便快速替换正文。
16. 作为清除输入的用户，我希望清除后保留焦点，以便立即继续输入。
17. 作为清除输入的用户，我希望清除只作用于当前输入，以便不会误提交、误删除或关闭输入区。
18. 作为使用空输入框的用户，我希望清除叉号隐藏，以便界面保持简洁。
19. 作为记录灵感的用户，我希望输入初始呈现一行的轻量外观，以便页面保持紧凑。
20. 作为编辑较长灵感的用户，我希望保留换行和长内容编辑能力，以便完整表达想法。
21. 作为熟悉现有快捷键的用户，我希望Enter提交及Ctrl+Enter换行保持现状，以便无需改变习惯。
22. 作为使用中文输入法的用户，我希望选字时不会误提交，以便正常完成输入。
23. 作为遇到保存失败的用户，我希望输入继续保留，以便直接重试。
24. 作为浏览灵感的用户，我希望主界面正文自动换行且最多显示两行，以便兼顾预览和列表密度。
25. 作为查看超长正文的用户，我希望两行以外的内容省略，以便列表保持整齐。
26. 作为便签用户，我希望新增灵感与新增任务使用一致的单行输入形式，以便无需切换操作习惯。
27. 作为便签用户，我希望两种类别的展开、清除、提交及收起方式一致，以便连续快速记录。
28. 作为便签用户，我希望灵感仍有自己的提示与视觉状态，以便知道当前记录的类别。
29. 作为新建主题的用户，我希望点击编辑区域外部等同于Esc取消，以便直接放弃未提交名称。
30. 作为修改主题的用户，我希望点击外部取消并恢复原名称，以便不会意外保存修改。
31. 作为编辑主题的用户，我希望输入区域内的清除和确认正常工作，以便不会被外部取消规则误判。
32. 作为浏览灵感的用户，我希望移除右侧详情面板，以便专注列表。
33. 作为浏览普通或已归档灵感的用户，我希望不再展示历史补充及追加入口，以便保持当前页面简洁。
34. 作为已有补充记录的用户，我希望数据继续保留，以便界面简化不会清理历史内容。
35. 作为修改灵感的用户，我希望继续在列表中原地编辑正文，以便不依赖详情面板。
36. 作为围绕主题整理灵感的用户，我希望主题视角位于时间视角之前并成为默认，以便先按主题浏览。
37. 作为首次进入或重启应用的用户，我希望默认进入未归类，以便快速记录和整理尚未分类的灵感。
38. 作为切换主题和时间视角的用户，我希望本次打开期间分别恢复分组和滚动位置，以便继续浏览。
39. 作为新建主题的用户，我希望在未归类分组项右侧看到加号，以便就近创建主题。
40. 作为浏览主题导航的用户，我希望新增主题入口只显示加号且有用途提示，以便兼顾简洁和可识别性。
41. 作为新增灵感的用户，我希望右侧新增灵感入口继续保留原职责，以便与新建主题区分。
42. 作为整理灵感的用户，我希望一条灵感继续允许归入多个主题，以便保留与不同想法的联系。
43. 作为在主题或时间视角整理灵感的用户，我希望现有归集入口继续可用，以便无需切换位置操作。
44. 作为归集灵感的用户，我希望主题勾选和取消勾选即时保存，以便无需统一保存。
45. 作为打开归集Popover的用户，我希望浮层在视觉上与当前行按钮关联，以便清楚知道操作对象。
46. 作为归集灵感的用户，我希望Popover宽度更紧凑，以便减少遮挡。
47. 作为关闭归集Popover的用户，我希望看到关闭叉号，以便明确退出操作。
48. 作为查找主题的用户，我希望继续搜索已有主题，以便快速定位。
49. 作为连续归集灵感的用户，我希望勾选或取消已有主题后浮层保持开启，以便继续多选。
50. 作为创建并归集主题的用户，我希望通过新主题输入框右侧的回车图标或回车键提交，以便减少按钮文字干扰。
51. 作为创建并归集主题的用户，我希望成功后浮层关闭，以便回到列表继续操作。
52. 作为创建主题失败的用户，我希望输入及浮层保留，以便修正或重试。
53. 作为关闭浮层的用户，我希望叉号、Esc和点击外部均可关闭，以便使用熟悉的退出方式。
54. 作为已完成部分归集的用户，我希望关闭浮层不撤销已经保存的勾选，以便保持即时保存结果。

## Implementation Decisions

- 提取共用返回列表组件，统一左箭头、文字、点击区域、留白及悬停和焦点反馈；接入保留详情的页面，任务详情为现有主要使用方。返回前原有草稿提交、失败保留及阻止离开的规则继续有效。
- 删除确认使用共用应用内弹窗，替代现有Electron系统确认框。覆盖任务、习惯、主题、已归档任务和已归档灵感中现有需要确认的删除入口；沿用应用视觉及主题色。
- 仅改变确认的呈现方式，删除执行继续经过受控桌面桥接和统一业务入口，保持窗口来源校验及交互保护。取消不写入删除；确认后调用原有删除用例。不得同时出现应用内和原生两次确认。
- 保留主题删除提示中的关联数量、永久删除的影响说明和不可恢复语义；普通任务归档、习惯任务暂停一次等原本无需确认的动作继续直接执行。
- 主界面新增灵感和正文原地编辑继续使用textarea，调整为初始一行的轻量外观，并接入清除能力。清除按钮仅在值非空且可编辑时显示；清除当前草稿并恢复焦点，不触发提交、删除或关闭。已有正文清空后仍受非空保存规则约束。
- 当前Input包装ClearableInput；显示清除按钮取决于显式清除回调、非空值和可编辑状态，没有按input的type筛选。灵感缺少清除操作源于textarea及新增编辑器未接入该能力；实施应覆盖已确认的灵感输入，避免只更换某类input的样式。
- 灵感的Enter提交、Ctrl+Enter换行、输入法组合输入保护、失焦保存及失败保留输入等提交逻辑保持现状。主界面非编辑正文最多显示两行，自动换行并在超出时省略；保留原地编辑完整内容的能力。
- 便签新增灵感与便签新增任务沿用一致的单行输入、展开、清除、提交及收起交互，保留灵感类别提示和视觉状态。当前便签没有灵感正文列表，本轮不新增该列表。
- 新建和修改主题的外部点击视为Esc取消；新建丢弃未提交名称，修改恢复原名称。输入区域内的清除和确认按钮均属于编辑区域，确认点击应正常提交。
- 移除灵感详情面板以及普通、已归档灵感的补充展示和追加入口；保留原地编辑正文，不用其他详情页替代。既有补充数据及相关接口继续保留，不修改灵感可持续补充的领域含义。
- 将主题和时间视角交换位置，主题在前并作为默认；首次进入和重启后默认未归类。本次打开期间分别恢复两视角的分组和滚动位置；移除详情后不再维护详情选中状态。不新增跨启动的浏览位置记忆。
- 新建主题入口仅显示加号，位于未归类分组项右侧，并保留悬停提示、可访问名称及键盘访问；右侧分组标题的新增灵感入口保持原职责。
- 继续采用多主题归集，不实施单主题限制及主题下隐藏归集入口的调整。保留checkbox勾选与取消即时保存，不清理现有主题关联，不需要单主题数据迁移。
- 归集Popover缩窄并锚定当前灵感行的触发按钮，展开时通过按钮状态及位置体现关系；增加关闭叉号，保留主题搜索和多选。
- 勾选或取消已有主题后保持Popover开启。移除创建并归集的文字按钮，改为新主题输入框右侧回车图标，支持点击和Enter提交；创建并归集成功后关闭，失败保留输入和浮层并反馈错误。
- 关闭叉号、Esc及外部点击关闭Popover，丢弃尚未提交的新主题输入，不回滚已保存的主题勾选。沿用跨窗口通知、失败反馈及现有分页与分组查询的一致性要求。
- 本轮没有已确定的新增数据库字段、补充接口变更或MCP协议变更。具体组件内部组织、尺寸与图标实现由实施阶段在现有分层及视觉规范内决定，未经讨论的像素值不列为用户确认条件。

## Testing Decisions

用户已确认以现有真实Electron操作链路及SQLite为主要验收边界，复用现有验证入口，不额外搭建独立测试接口。

- 好的测试只断言用户可观察行为和持久化结果，不绑定React私有状态、组件拆分、内部调用次数或SQL写法。可逆样式调整使用简短视觉检查，不编写镜像测试。
- 测试模块包括主界面灵感管理、主题编辑和归集、便签新增输入、任务详情返回及各类删除确认；通过界面贯穿桌面桥接、统一应用服务和真实SQLite。
- 复用已有Electron灵感、任务及便签归档验证的先例，使用现有隔离数据目录、双窗口变更及重启验证方式；将旧系统删除确认的模拟或断言更新为应用内确认操作，不保留依赖原生弹窗的错误前提。
- 验证新增及原地编辑的清除显示条件、清除后焦点和不误提交，覆盖空内容校验、Enter、Ctrl+Enter及输入法组合输入；验证原失焦保存、失败保留草稿和连续新增结果。
- 在便签切换任务和灵感，验证单行输入形式及展开、清除、提交、收起一致，保留类别提示，新增结果同步主界面。
- 验证新建和修改主题点击外部及Esc取消，内部清除和确认不被误判；验证新建主题加号位于未归类右侧且可通过键盘访问。
- 验证默认主题视角、未归类初始分组、视角切换恢复分组和滚动位置、重启默认未归类；详情和补充入口消失，已有正文仍可原地编辑，已有补充数据保持可读取。
- 验证多主题勾选即时保存且浮层保持开启，搜索可用；创建新主题并归集成功后关闭，失败保留输入与浮层；关闭不回滚已保存勾选。复用现有跨窗口和重启结果验证主题关联保存。
- 验证各类删除入口只出现一次应用内确认，取消不删除、确认结果正确；删除主题保留灵感并显示关联数量，永久删除结果符合原规则。归档和暂停一次继续无需删除确认。
- 在正常宽度及窄窗口进行简短视觉检查，覆盖返回按钮点击区域、两行正文、主题加号、Popover紧凑布局及触发关系、删除弹窗与主题色一致性。
- 界面验证难以稳定构造的失败和保留数据场景，优先补充现有AppService公开接口配合真实SQLite的集成验证，不为每一层重复写测试。实施完成时执行类型检查、构建及受影响的现有回归。

## Out of Scope

- 本次规格发布不实施业务或界面代码，不创建PR或部署。
- 单主题限制、主题下隐藏归集入口及既有多主题关联迁移。
- 删除历史补充数据、移除补充接口或修改MCP协议。
- 新增灵感详情替代页、补充展示或追加入口。
- 改变灵感提交快捷键、失焦保存、输入法处理或现有业务删除规则。
- 为归档、暂停一次等直接操作新增确认弹窗。
- 便签整体布局改版或增加便签灵感正文列表。
- 将任务、习惯的全部输入控件纳入统一清除改版。
- 主题合并、排序、层级管理、跨启动浏览位置记忆、AI归集或灵感转任务。

## Further Notes

- 需求及验收边界来自2026-11-02的两轮对齐，用户已整体确认“准确”，本轮按to-spec直接综合并发布，应用ready-for-agent标签。
- 这是已确认灵感分组导航能力上的后续细节调整，可结合[Issue #18](https://github.com/SEVEN-TSY/dook/issues/18)理解已有行为；本Issue中明确的新规则优先，不重新引入已撤回的单主题要求。
- ADR0001及旧规格中的默认按日期、正文最多三行、保留右侧详情，由本轮默认按主题、正文最多两行及移除详情替代。多主题归集语义继续保留。
- 原主界面视觉规范中Textarea不增加清除操作的描述，需要在实施时按本轮灵感输入决定同步更新，其他输入不因此自动扩展范围。
- 相关需求、视觉和工程文档在实施时同步到最终行为。现有灵感领域定义仍允许持续补充，本轮移除的是界面入口，无需新增领域术语或架构ADR。
- 规格记录实施范围，不表示功能已经完成；需求整理期间不覆盖当前工作区其他未提交修改。
