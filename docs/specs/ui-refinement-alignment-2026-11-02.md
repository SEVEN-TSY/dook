# 界面细节调整对齐记录

2026-11-02。状态：用户已整体确认需求及验收边界，正式规格已发布为[GitHub Issue #27](https://github.com/SEVEN-TSY/dook/issues/27)，现已在`codex/issue-27-integration`完成实施，见[实施验收记录](../reviews/issue-27-review.md)。本记录保留对齐过程；开发及验收以正式规格和实施结果为准。

## 已明确的要求

### 1. 共用返回列表入口

- 使用左箭头及“返回列表”文字，增加留白和点击高度，提供完整的悬停、键盘焦点状态。
- 提取为共用组件，统一其他页面的同类返回入口；任务详情使用该组件。
- 返回前已有的草稿保存及失败保留行为保持现状。

### 2. 共用应用内删除确认

- 以应用内共用弹窗替代当前系统原生删除确认，沿用应用的主题色、字体、圆角、按钮和焦点风格。
- 范围包括任务、习惯、主题、已归档任务及已归档灵感中现有需要删除确认的入口。
- 确认、取消及业务删除规则保持现状；取消不修改数据，确认后才执行删除。
- 删除主题继续保留灵感，并提示关联灵感数量；永久删除仍清楚说明不可恢复及影响范围。
- 普通任务归档、习惯任务暂停一次等原本不需要删除确认的操作，不因此增加确认弹窗。

### 3. 灵感输入外观与清除

- 主界面新增灵感和正文原地编辑保留textarea，只调整外观并补上清除叉号。
- 初始呈现一行输入的轻量外观，保留长内容编辑及换行能力；主界面非编辑状态正文自动换行、最多显示两行，超出省略。
- 有内容且可编辑时显示清除叉号，空内容时隐藏；点击仅清空当前输入并保持焦点，不提交、不删除已有灵感、不关闭输入区。
- 提交逻辑保持现状，包括Enter提交、Ctrl+Enter换行、输入法选字保护、已有失焦保存规则和失败保留输入。
- 便签新增灵感与便签新增任务保持一致的单行输入形式，沿用同一套展开、清除、提交及收起交互；保留灵感类别自己的提示和视觉状态。本轮不新增便签灵感正文列表。
- 不将清除能力扩展为本轮所有任务、习惯输入的统一改版。

### 4. 主题编辑的外部取消

- 新建、修改主题时，点击编辑区域外部等同于Esc取消。
- 新建时丢弃未提交名称；修改时恢复原名称，不保存未确认的改动。
- 输入区域内的清除和确认按钮属于编辑区域，点击确认正常保存。

### 5. 灵感页面简化及默认视角

- 移除灵感详情面板、历史补充展示及追加补充入口，普通灵感与已归档灵感均不展示补充内容。
- 既有补充数据保留，本轮不删除数据、不移除或修改相关接口。
- 保留列表正文的原地编辑，不新增其他详情页替代被移除的面板。
- 主题和时间视角交换位置，主题在前，默认按主题。
- 首次进入及重启后选择未归类；本次打开期间两种视角分别保留分组及滚动位置。详情移除后不再记忆详情选中状态。
- 新建主题入口仅显示加号，位于未归类分组项右侧，并提供悬停提示及可访问名称；右侧分组标题的新增灵感入口保持原职责。

### 6. 主题归集维持多选

- 撤回单主题限制，继续允许一条灵感归入多个主题。
- 不实施主题下隐藏归集操作的调整，各视角现有归集入口保持现状。
- 勾选和取消勾选继续即时保存，不增加统一保存按钮，不迁移或清理既有主题关联。

### 7. 归集Popover

- 缩减宽度，增加关闭叉号，在位置与触发按钮状态上体现从当前灵感行展开的关系。
- 保留主题搜索、多选及即时保存。
- 选择或取消已有主题后保持Popover开启，支持连续整理。
- 创建并归集不使用文字按钮，改为新主题输入框右侧的回车图标；点击图标或按回车提交。
- 创建新主题并归集成功后关闭Popover；失败时保留输入和浮层，沿用现有错误反馈。
- 点击关闭叉号、按Esc或点击浮层外部可关闭；关闭只丢弃尚未提交的新主题输入，不撤销已经保存的勾选结果。

## 已确认的验收边界

以下验收边界已随需求一并获得用户确认。

- 在主界面正常及窄窗口检查返回入口、两行正文、新建主题加号和Popover布局，确认按钮可点击、可聚焦且不遮挡内容。
- 验证新增及原地编辑的清除叉号、清除后的焦点、空内容校验、Enter、Ctrl+Enter和输入法组合输入；保持原提交及失焦保存结果。
- 便签切换任务和灵感，验证新增输入形式一致，连续输入、清除和收起行为保持一致。
- 验证新建及修改主题点击外部取消、Esc取消、内部确认正常保存。
- 验证默认主题视角及未归类、两视角切换恢复位置；详情及补充入口均移除，已有补充数据保留。
- 验证多主题即时保存、选择已有主题后浮层保持开启、新主题创建并归集成功后关闭、失败保留输入及浮层。
- 验证现有各类删除入口使用一次应用内确认，取消不删除、确认结果正确；保持归档与暂停一次无需确认的行为。
- 复用现有真实Electron及SQLite验证入口；实施时执行类型检查、构建及受影响的现有回归，不为可逆样式调整单独搭建镜像测试。

## 已核实的当前实现

- 主界面新增灵感与正文原地编辑均使用textarea；新增及编辑沿用Enter提交、Ctrl+Enter换行及输入法组合输入保护。
- Input包装ClearableInput。清除按钮需要显式传入onClear、当前值非空且控件可编辑，不按input的type筛选；Textarea和InlineComposer没有接入此清除能力。
- 桌面便签当前仅显示灵感数量和新增入口，没有灵感正文列表。便签新增灵感使用可清除的单行输入框。
- 当前灵感支持多个主题，归集Popover使用checkbox即时保存，本轮保留该规则。
- 灵感详情是当前历史补充展示和追加内容的入口。
- 任务详情和灵感详情各自内联返回按钮，目前没有共用返回组件。
- 当前删除确认由主进程调用Electron原生系统弹窗，应用内CSS不会作用于该弹窗。

## 与旧规格的关系

- 旧规格及ADR0001中的默认按日期、正文最多三行和保留右侧详情，由本轮确认的默认按主题、正文最多两行及移除详情替代。
- 保留多主题归集语义，无需单主题迁移。
- 主界面设计语言中“Textarea不增加清除操作”的旧描述，需要按本轮灵感输入的决定更新；本轮未要求将所有textarea统一改造。
- 现有补充数据及相关接口保留，领域术语中的灵感仍允许持续补充，不将界面入口移除误写为领域能力删除；本轮无需新增术语或架构ADR。
- [Issue #27](https://github.com/SEVEN-TSY/dook/issues/27)作为本轮开发和验收依据；相关旧文档在实施时同步调整，避免将旧规则继续作为验收标准。
- 当前工作区已有其他未提交修改，本次仅维护本讨论文档，不覆盖其内容。
