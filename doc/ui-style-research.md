# myTodo整体UI风格与审美调研

调研日期：2026-10-27。状态：**用户已确认“蓝白简约、偏工作氛围的桌面便签”**，以用户提供的桌面参考图为基准。最终规则见[UI风格规范](./ui-style-guide.md)。本文保留一手资料与候选方案作为决策依据。

本文将外部资料中的事实与myTodo的设计建议分开。候选名称、配色、尺寸及布局均为本项目提案，不代表参考产品或设计系统的原厂规范。

## 1. 设计需要服务什么

依据[需求文档](./todo.md)，myTodo是Windows个人任务工具：开机启动、托盘常驻、快速唤出、贴边隐藏；用户短暂打开窗口，记录或查看任务，再回到手头工作。今天任务、多天任务、习惯生成的任务共享一张列表；灵感默认折叠，可逐渐补充内容。Agent通过MCP操作数据，产品当前没有内嵌AI聊天的需求。

调研开始时，[窗口代码](../src/main/desktop/window.ts)和[应用服务](../src/main/core/app-service.ts)处于工程验证阶段，没有必须继承的产品视觉语言。技术骨架中的背景色与诊断页面未作为审美依据。

**设计判断：**主界面应呈现安静、反应迅速、可随时收起的个人工具感。决定质感的重点是字体层级、列表节奏、对齐和交互反馈。顶部大横幅、装饰性统计卡、持续动画会占用原本留给任务的注意力。

## 3. 三个候选方向（调研记录）

三个方向使用同一组任务和同样的业务规则。比较的是整个界面的气质、密度与空间组织；浅色与深色主题可以在确定方向后分别扩展。

| 维度       | 清爽原生，推荐                                 | 温润纸感                                               | 紧凑工具                               |
| ---------- | ---------------------------------------------- | ------------------------------------------------------ | -------------------------------------- |
| 感受       | 清晰、轻快、熟悉、可信赖                       | 放松、个人、适合思考与积累                             | 精确、克制、操作导向                   |
| 参考依据   | Fluent的字体、颜色角色与布局；Things的渐进展开 | Things的内容优先；以编辑排版形成纸面感，属于本项目创作 | Linear的视觉降噪与信息密度             |
| 明亮主题   | 浅冷灰框架、白色内容、蓝色点缀                 | 暖白背景、浅米色辅助区域、鼠尾草绿                     | 中性浅灰、白色或微灰表面、低饱和紫     |
| 空间结构   | 左导航＋主列表＋按需打开的详情                 | 上导航＋偏文档式正文＋页边注式详情                     | 窄导航＋密集列表＋常驻详情             |
| 字体       | 全部系统无衬线，正文清楚稳定                   | 正文系统黑体，大标题可少量使用衬线                     | 系统无衬线，数字/快捷键可使用等宽字体  |
| 列表       | 均匀行距，轻分隔，元信息安静                   | 留白更宽，阅读节奏更慢                                 | 行距更紧，信息成列、对齐更强           |
| 圆角与层次 | 适度圆角，边框轻，浮层少量阴影                 | 更平面，依赖文字层级和留白                             | 小圆角，灰阶区分区域，边框低对比       |
| 更适合     | 高频打开、勾选、录入与一般日常使用             | 灵感记录较多、偏好个人笔记氛围                         | 同时跟踪较多多天任务、偏好键盘与密度   |
| 取舍       | 个性较克制，需要靠细节形成辨识度               | 同屏任务较少，需控制装饰字体的使用                     | 空间更拥挤，首次使用需更明确的操作提示 |

## 4. 最初推荐：清爽原生（调研记录）

**设计判断：**清爽原生最符合当前已确认的使用方式。myTodo需要处理今天任务、习惯、长期进度和灵感，但用户每天最常发生的动作仍是打开、看一眼、输入、勾选。清爽的列表结构容易承载这些动作，同时给后续功能保留空间。蓝色承担主要操作与选中提示，完成状态单独使用稳定的语义反馈。

这里的“原生”是熟悉的Windows使用感与视觉节奏，不要求改用WinUI，也不意味着直接套用某个组件库。Electron＋React可以沿用当前技术选型。

建议形成四条统一原则：

1. **内容清楚。**任务标题是视线第一落点；导航、日期、标签和进度依次后退。
2. **空间有秩序。**主要依靠间距、对齐和少量分隔建立层级；每条任务保持相同的左右锚点。
3. **色彩有职责。**一种主强调色，少量状态色；习惯、任务和灵感不各占一个大色块。
4. **操作轻而明确。**输入后即可保存；选择任务再展开完整细节；反馈简短、紧邻操作位置。

## 5. 落到整个产品的建议

### 主列表

- 今天任务在上，多天任务在下，使用小标题与细分隔；仍属于同一个任务列表。
- 习惯生成的今天任务直接参与列表，可用小型重复图标标识来源；习惯管理页负责配置。
- 普通任务呈现标题、必要标签和状态。多天任务增加细进度条与百分比，进度可拖动。
- 已完成任务留在原有位置，以勾选、柔和文字和必要的删除线表达完成，避免整体过浅导致难以回看。
- 灵感默认只显示折叠标题与数量，展开后显示记录；追加内容在该灵感的详情中完成。
- 置顶与拖动操作可在悬停、选中或键盘聚焦时显露，保持默认列表安静。

### 详情、设置与Agent信息

- 详情沿用主列表的字体、灰阶和间距，负责子事项、补充内容、预计天数与进度编辑。
- 设置页按“窗口与启动”“类别”“Agent连接”等实际配置分组；开关、说明和保存反馈使用同一套组件。
- Agent连接状态与地址放在设置中；需要追踪修改来源时，可在详情显示轻量记录。主页面无需增加聊天框或固定AI侧栏。
- 空状态用一句明确提示与新增入口即可；错误提示接近出错操作，保留用户已输入内容。

### 尺寸与字体建议

清爽原生可从以下参数开始，均为myTodo提案：

| 项目     | 起点                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------- |
| 字体     | `"Segoe UI Variable", "Segoe UI", "Microsoft YaHei UI", "Microsoft YaHei", system-ui, sans-serif` |
| 任务正文 | 14px，常规字重；选中或标题按需使用600                                                             |
| 辅助信息 | 12px，保持足够对比                                                                                |
| 页面标题 | 24px左右，字重600，避免超大展示字体                                                               |
| 任务行   | 单行约48–56px；元信息或进度增加时自然增高                                                         |
| 图标     | 16–18px，统一笔画与视觉重量                                                                       |
| 间距     | 4/8/12/16/24/32px，以内容关系选择                                                                 |
| 圆角     | 常规控件约8px；小标签可以更小                                                                     |
| 动效     | 状态反馈约100–160ms，局部展开约160–220ms；响应系统减少动态效果偏好                                |

字体栈和尺寸需要在用户实际Windows缩放比例与中英文混排下微调。紧凑方向可以缩短行距，但正文不宜为了塞入更多任务而同步大幅缩小。

### 材质建议

首版可使用纯色表面和少量层次，窗口、菜单和浮层保持一致。微软将Mica用于窗口基础层，将Acrylic用于短暂浮层；这些材质各有明确作用。[Windows材质说明](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/materials)

本项目建议先把排版与状态做扎实，再根据真实桌面效果选择是否加入原生材质。当前资料不提供myTodo的性能实测，不能据此承诺材质或动画的资源占用。

## 6. 如何作最后的审美决定

使用同一组真实内容比较三版完整窗口：短标题、长中文任务、习惯任务、两个多天进度、一个已完成项、折叠灵感，以及展开后的详情。这样可以判断喜欢的是配色、字体、密度还是布局。

用户已通过桌面预览与参考截图确认整体方向为蓝白简约、偏工作氛围。颜色角色、字体层级、间距及组件规则已整理到[UI风格规范](./ui-style-guide.md)，后续产品界面按该基准推进。上面的三个候选保留为调研资料。

## 7. 用户补充：桌面固定状态与工作习惯

用户进一步明确，优先需要观察固定在桌面时如何展示任务及完成操作。完整主窗口的预览不足以支撑这项审美决策；下一步以桌面常驻面板为评审对象。

习惯优先指工作习惯与固定、重复的工作内容，生活习惯其次。界面示例和默认文案优先使用检查项目构建状态、更新工作进展、整理每日待办等工作事项；数据模型继续允许用户添加生活习惯。[需求记录](./todo.md)

桌面面板采用约334px宽的紧凑列表，放在桌面右侧，取消侧栏和常驻详情。今天任务在上，多天任务在下，习惯生成的任务参与同一列表；直接勾选、拖动行内进度、输入并回车新增。任务标题打开临时编辑浮层，灵感默认折叠；顶部可锁定位置、贴边收起，边缘入口用于再次展开。这些行为已通过交互预览演示，实际桌面窗口行为按产品功能需求实现。

用户补充常驻形态为类似钉在桌面的便签，并最终选择参考图中的蓝白简约效果：冷白表面、少量蓝色强调、轻圆角、柔和阴影、紧凑工作清单。管理页与桌面便签共用任务状态、图标和排版规则；用户提供的截图已保存为[视觉基准](./assets/ui/desktop-style-reference.png)。
