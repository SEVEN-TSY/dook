# 贴边胶囊与便签过渡调研

调研日期：2026-10-28。依据用户本轮反馈：细条悬停时立即消失，胶囊整体向屏幕内侧推出；离开时胶囊推回屏幕边缘并消失，之后细条弹回。胶囊与便签应有连续的表面交接，避免裁切刷出或逐帧拉大窗口宽高的观感。下述方案是myTodo的实现判断，不代表复刻macOS某一项系统动画。

## 一手资料与方案比较

| 方案 | 可验证依据 | 对本项目的判断 |
| --- | --- | --- |
| 共享元素布局动画 | Motion用`layoutId`连接两个状态，通过CSS`transform`完成位置和尺寸投影；内容可单独交叉淡入。缩放可能拉伸文字、圆角和阴影，官方建议对子元素和圆角做校正。[Motion官方布局动画](https://motion.dev/docs/react-layout-animations) | 适合胶囊到便签的连续表面交接；表面与内容必须分层，不能把整张任务列表直接缩成胶囊。 |
| View Transitions | 浏览器捕获旧、新状态快照，配对后过渡位置、尺寸和内容；同一时间只有一个过渡，新过渡会让旧过渡跳到结束。[Chrome官方说明](https://developer.chrome.com/docs/web-platform/view-transitions/same-document) | 可以做页面或卡片共享过渡，但频繁hover、快速移入移出及原生窗口视口切换会增加交接复杂度，当前不优先采用。 |
| 弹簧运动 | Apple强调连续的位置与速度；弹簧可在目标变化时保留已有速度。弹簧也可以无明显回弹，多个属性不必同时起止。[AppleWWDC23：Animate with springs](https://developer.apple.com/videos/play/wwdc2023/10158/) | 重点是连续接力和自然停稳，不能只加一条带回弹的缓动曲线，就宣称获得系统级动画。 |
| 原生窗口尺寸动画 | Electron的`setBounds`会改变原生窗口边界，`animate`参数只标记支持macOS。[Electron BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window#winsetboundsbounds-animate) | Windows应先提供足够透明绘制空间，再在渲染层做视觉动画；动画期间不逐帧调整原生窗口宽高。 |

## 推荐实现：独立共享表面＋WAAPI投影

沿用React和Web Animations API，不为两个固定状态新增整套动画依赖。WAAPI提供关键帧、时间控制、取消与完成状态等机制；具体生命周期以`Animation`完成或取消为准。[W3C Web Animations规范](https://www.w3.org/TR/web-animations-1/)

1. **细条、胶囊、过渡表面、便签内容分别建层。**细条不复用胶囊DOM，不让细条原有的居中`transform`参与胶囊插值。悬停意图成立时先隐藏细条，准备胶囊的静止初始位置，再向内侧平移胶囊。胶囊数字保持同样尺寸并随整个胶囊移动。
2. **退出反向推回边缘。**左侧胶囊向左推入边缘并淡出，右侧向右，上侧向上；退出结束后再显示细条，给细条独立、短促的弹出动画。进入和退出方向相反，退出完成后才恢复细条。
3. **胶囊到便签使用空白共享表面做FLIP。**先测量胶囊和便签的屏幕矩形，扩展透明原生绘制空间，并把胶囊矩形换算到新视口。过渡表面按便签终态布局，初始投影为`translate(source.x-target.x, source.y-target.y) scale(source.width/target.width, source.height/target.height)`，再平滑归位。这样只有一个有持续身份的表面，不会一边露出便签、一边留下另一层胶囊边框。
4. **内容不跟着表面非等比缩放。**胶囊数字先退场，任务列表在表面扩展到足够范围后以原始字号淡入；任务列表始终按最终尺寸排版。反向过渡时先退任务内容，再把共享表面交接回胶囊。不要缩放整张任务列表，否则会产生被挤扁后突然恢复的文字。
5. **圆角跟随表面实际尺寸校正。**若本帧缩放为`sx, sy`、期望屏幕圆角为`r`，可给共享表面设置椭圆圆角`r/sx`和`r/sy`，再由`transform`投影为期望圆角；逐帧关键帧同步表面投影和圆角，而不直接把胶囊圆角线性写成便签圆角后整体拉伸。淡入后的真实便签接管最终边框与阴影。
6. **中断从当前画面接力。**新意图先记录当前表面矩形和透明度，再取消旧动画，从当前状态启动目标动画。为每次过渡保留generation，迟到的`finished`或计时器不能覆盖新状态。销毁时统一取消动画、鼠标轮询和完成回调。

这里的FLIP是“先确定布局，再反向投影并播放”，不是把原生窗口或内容宽高逐帧拉大。数值可先尝试胶囊进入约240–300毫秒、退出约160–200毫秒、表面交接约380–460毫秒；这些是项目调参起点，最终以录屏和真实交互观感为准。

## 原生视口的边界

胶囊退出时需要额外内侧空间，否则平移未结束就会被透明窗口边界截断。胶囊到便签开始时扩到最终便签视口，动画结束后再交给真实便签；收起时先完成表面动画，再缩原生视口。几何坐标统一以屏幕坐标换算，重点验证右边缘、上边缘以及不同Windows缩放比例。

## 验收信号

- 悬停意图成立后，细条无描边变色、无位置抖动，直接隐藏。
- 胶囊进入时宽高不变，整个胶囊与数字一起平移；退出时反向推回屏幕边缘并淡出。
- 退出完成前细条不可见，之后细条从固定位置弹回。
- 胶囊到便签只有一个连续表面，圆角不被横向拉长；列表文字没有非等比缩放。
- 快速移入移出、动画中再次点击、拖动及窗口销毁时不闪回、不留影、不抛异常。
- 使用实际动画的分段截图或录屏评估观感，不能只以“状态字段正确、构建通过”作为流畅度结论。
